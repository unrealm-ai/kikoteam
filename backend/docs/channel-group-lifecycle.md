# 飞书群生命周期

Manager 是群/成员状态和业务准入的权威所有者；Platform 维护绑定与通讯录，Event Hub 仅对接飞书 SDK 事件和远程查询。迁移 `000025` 增加 Manager 的事件去重、群状态、成员状态，并在既有渠道 ACL 上叠加群门禁，不改变部门/个人授权。

## 可信事件与状态

Hub 注册机器人加入/移除、群解散、用户加入/删除/撤回六种事件。校验应用、租户、事件 ID、chat ID 和提供方时间；毫秒与飞书微秒头时间统一为毫秒。成员以 open_id 去重，不以显示名或操作人身份推断成员。普通用户退出只改变该用户，不推断机器人退群。

内部 `/api/internal/v1/channel-lifecycle` 复用 Hub 服务认证。Manager 在绑定锁内复验启用、generation、revision、tenant，并在一笔事务内持久事件和状态。去重作用域为 binding + identity_epoch + tenant + event_id；相同 ID 不同业务内容返回 `event_conflict`。连接代次和配置版本不进入业务内容指纹，因此重连后的同事件可返回原回执。旧代次回调仍拒绝。

- 机器人加入/退出先设 `pending`，立即隔离群出站，再安排远程当前在群核验。旧时间事件不覆盖较新水位；相同时间采取保守重新核验。
- `chat_disbanded` 是当前 binding identity_epoch 下终止墓碑，即使较迟到达也不被后续加入/消息复活。
- 用户成员事件逐身份维护时间水位，相同时间退出优先，不影响其他成员或整个群。
- `present` / `absent` 只由成功的 `is_in_chat` 查询产生。超时、403、非零 provider code、缺失布尔字段均是未知，保持 `pending`，不能当作已退群。
- 不曾收到群生命周期证据的普通群消息保持既有准入行为，不额外引入每条消息远程依赖。

## 持久核验与恢复

Hub 在 elected 生命周期中轮询 `/channel-groups/claim`（每次最多 5 条），使用对应绑定访问飞书 `im/v1/chats/{chat_id}/members/is_in_chat`，将布尔结果或未知提交 `/channel-groups/{id}/complete`。

Manager 30 秒核验租约、事件更新使旧 lease 失效；完成时再次核对启用、identity epoch、tenant、generation 和 revision。新事件覆盖或换绑后迟到的结果不能激活群。异常采用 30 秒逐次增长至 5 分钟的退避，持续重试且保持隔离；重启/主备接管可重领过期租约。单次远程请求 10 秒超时。未知结果不会删除待核验状态。

已确认 absent 后，一条晚于离群水位的实时群消息可重新进入 `pending` 核验，修复漏收重新入群事件；该消息仍保存在 inbox，不提前执行。成功核验后才继续原输入。旧消息不能复活群，解散群不能复活。待核验群不阻塞其他聊天的 inbox 处理。

## 出站与执行隔离

群门禁叠加在 `manager_channel_actor_allowed`，供输入执行和历史上下文授权共同使用。固定拒绝消息也必须经过群门禁，不能借固定回复绕过退群状态。

撤权事件事务取消当前 pending/leased 投递；重新入群不复活这些投递。投递授权再次检查当前群/成员状态，并拒绝来源消息早于群/成员水位的输出，防止退群后迟到物化的旧答复发入新会话阶段。Manager 已接受的业务历史不删除，也不归档 Web 会话。

授权事务与生命周期事务通过绑定锁排序。已经越过发送授权裁决点、实际发往提供方的外部请求无法撤回；这不是 exactly-once 或零网络竞态承诺。旧 sending 租约未知结果沿既有投递恢复处理，绝不盲目重发。

## 验证范围

新增真实 PostgreSQL 用例覆盖重复/冲突、跨租户与代次拒绝、乱序水位、解散终止、旧核验 lease、成员与机器人分离、未知重试、消息触发恢复、排队投递取消和重入后旧输出隔离。Hub 用本地 HTTP stub 验证 provider 错误/缺字段保持未知、绑定变化及租户不匹配不核验/不提交旧结果。HTTP 入口另覆盖服务认证与非法输入。生产飞书应用事件订阅、scope 和真实租户端到端仍需部署验收，本轮没有向外发送消息。
