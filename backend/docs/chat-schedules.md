# 主对话定时任务

主对话为明确要求自动执行的工作保存计划；「先记下来，稍后我喊你再做」仍是手动待办。业务触发器执行与固定提醒后端不变。页面隐藏新建入口和历史固定提醒配置。迁移 116 停用已有固定提醒并删除尚未开始发送的通知，保留配置、发送中或终态历史和后端能力；回退不会自动重启。主对话里请求到点提醒本人时，使用会话定时任务；每次执行的目标是输出提醒文案，由原对话的正常任务回告送达，无单独提醒工具。

| MCP | 必填 | 用途 |
| --- | --- | --- |
| `task_delegation_create_scheduled_task` | `instruction`、`schedule` | 创建计划，返回计划 ID、规则及未来执行时间；不立即建任务 |
| `task_delegation_list_scheduled_tasks` | 无 | 当前用户在当前对话的计划；传 `schedule_id` 查询单条及最近 20 次执行回执 |
| `task_delegation_update_scheduled_task` | `schedule_id` | 提供改动字段，使用 `enabled` 启停，或单独传 `cancel=true` 取消未来执行；已生成的任务不受影响 |

`instruction` 与普通任务一致，保存必要上下文、目标、约束、独立审批前提和交付物，不夹带调度指令或依赖整段历史。可选标题和来自该对话的已授权附件引用；创建时检查，执行时重新校验。修改任务内容或时间不暗中替换附件。模型不提供身份、工作区、会话或去重键。

## 日历

`frequency=once` 使用带时区偏移的分钟精度 RFC3339 时间；`hourly` 支持每小时指定分钟，或 `interval>1` 表示以保存或重新设置时的分钟为锚点的小时数；`daily`、`weekly`、`monthly` 使用一到多个 HH:mm，后两者分别指定 ISO 星期和月中日期。月中 `-1` 为月底；缺失的某月日期或不存在的夏令时时间跳过，重复的本地时刻只用第一次。默认 Asia/Shanghai，明确个人时区时覆写。

## 触发与权限

计划存入独立的 Manager 表，复用现有 Event Hub 领导者扫描与 tick。新 Hub 通过 `include_chat=true` 选择接收对话计划，并原样回传 `kind=chat`；旧 Hub 仍只看到现有触发器。扫描、续排用数据库时间；接管跳过停机错过的执行，不回放一串历史任务。

写计划使用真实活跃输入；同一输入相同参数只受理一次。到点校验已保存的计划 ID、版本、时间、原对话及创建人的当前授权，不要求主对话仍有活跃轮次，也不伪造主对话消息。新 Task/Session/Input、来源绑定、计划续排与 occurrence 回执同事务提交；同计划同一时刻最多一条任务。已取消或编辑后的旧 tick 无效；明确拒绝或错过单独记录为 skipped，不假造任务或执行结果。成功提交的任务沿用 Conversation 沙箱、执行历史、详情及原对话回告。

计划记录仅由原对话的创建主体管理。当前任务列表可照常查真实任务；计划回执用 task ID 关联已有详情。验收覆盖：空闲对话并发重复 tick、撤权/归档、原对话正常回告、日历边界与已有业务触发器兼容。

## 页面管理

在既有触发器面板使用「定时触发」「事件触发」「会话定时任务」三个区块，不新增员工详情的一级页签。对话定时显示渠道、私聊或群聊来源、日历与下次执行。工作区 owner/admin 和有当前员工管理权限的 Web 身份可读配置、改时间、启停；普通使用者只在创建计划的原对话通过工具操作自己的计划。页面不能创建、删除、取消、变更工作要求或切换来源。更新须提交版本，启停只影响未来，不重新归属、改变授权主体或补跑。

「今晚」「明天」由主对话每轮的可信系统时间解释，默认 Asia/Shanghai；只用于本轮推理，不修改已持久化的用户消息或任务指令。
