# 渠道私聊确认、短答与消息上下文

## 通知与确认定位

- 任务停稳后才创建主动通知。每个请求、版本和指派确认人有独立投递记录。工作台仍可查询 Web 确认；飞书、钉钉、企微发送私聊，企微指派仍要求事先绑定验证。旧待确认不会在升级时批量补发。
- 主动通知按背景、问题、后续动作和影响范围展示。多题编号，必答标记和答题条件跟随对应问题。审批题说明同意后的动作，有必答项时请用户同时回答并明确同意。信息题说明收到答复后的动作，直接请用户提供答案。
- H- 短码指向当前版本的确认单。首版也兼容完整请求 ID；换人后的旧短码和旧引用不延续。飞书识别受信任回调的私聊 parent_id，并与机器人实际送达的消息 ID、私聊 ID、租户、确认人、绑定及版本比对。钉钉的发送查询标识和企微的连接回执不是引用 ID，不能用作引用凭据。
- 私聊回复进入主对话 Agent。查询工具提供当前真实消息片段、可信引用和已发出的澄清焦点。Agent 判断单条或多条确认的归属、是否还需澄清，以及逐项答案和决定。编号、送达回执和版本是证据；Manager 根据 Agent 的提议校验身份、题目范围和证据冲突，并检查必答项。
- 已定位但还需澄清时，登记追问正文。Web 只从已完成的对话回复取证，渠道须有已送达回执；下一轮只把实际可见的追问作为可信焦点。提交明确答复后按原输入授权续跑。
- 渠道确认专用轮次按当前已指派问题准入，仅装配确认工具。普通私聊可继续原有对话与委派。用户在工作台表单要求补充时，保留待确认并记录来源。退回修改进入只开放确认工具的整改轮次，原任务等待新单批准。拒绝终止任务。
- 飞书还可以引用经核验、实际送达且对应已登记追问的 Agent 回复。原任务只收到核验后的结果。

## 旧固定回复退役

业务答复、澄清和结果说明由主私聊 Agent 生成，通过普通 `reply` 投递。通用渠道异常文案和确认工具提示沿用原入口。

旧 `human_confirmation` 渠道回复的生成和专用投递授权已移除。历史正文、原入站和答复仍可读取。已有发送尝试继续按原操作核对供应商回执，确认送达后可补记历史。澄清焦点使用实际送达且登记过追问的 Agent 回复。

## 管理员补救与续跑优先级

员工详情的「设定与模型 → 人工确认投递与补救」只对工作区 Owner/Admin 展示。状态包含待发送、已发送、确认中、失败、送达未知，以及任务停稳待核对；不回显确认题目和答复。只有能证明未发送且没有任何已提交答复时可重试或改派，须填写原因。动作记录操作者和请求版本，旧短码失效；已发送、正在发送或结果未知时不盲目重发、不允许代答。

保留现有执行队列优先级：有权继续的人工确认或事项验收结果在原等待任务中先于普通积压输入。确认人私聊是独立的会话，不受这个顺序影响。退回修改后，整改 Agent 可为新草案发起确认。原任务在新单批准前持续等待。
