# 能力包的固定会话场景

每个包独立配置 `conversation_scope.private` / `.group` 与 `trigger_scope.enabled`。会话规则有 `enabled`、`mode`、`allow`、`deny`；模式固定为 `inherit_with_blacklist`（allow 必须空）或 `allowlist`（deny 必须空）。私聊可选人员/部门，群聊可选人员/部门/群，实际支持的渠道目录类型与现有统一选择器一致。群白名单人员或部门属于同一类别 OR，群属于另一类别；已配置的类别均须匹配，无任何类别不授权。任一黑名单命中拒绝，适用但不确定的部门/身份代次拒绝。

包层永不授予员工使用权。先核验可信运行来源、员工准入及活动 Input，再按数据库中的真实私聊/群聊来源判断；原始能力快照与当前配置分别检查取交集。手工用户 TaskSpace 保持个人 Web 场景授权，不视为群；可信 Trigger 独立判断，不借人类身份或私人场景。包规则不禁用基础内置工具。

## 旧配置与快照

迁移 55 只增加 nullable JSON 列，不回填权限。它拒绝直接回退：旧 Backend 不理解已写入数据库及历史快照的场景限制（包括触发器停用）。切换时先迁移，不能混用旧 Backend 继续解释新策略。`conversation_scope=null` 的包及旧快照继续运行原 `scope` 算法，包括旧 `whitelist_with_blacklist`，不转成新的纯白名单；尤其不能把带 Web 名单旧包自动复制到所有 IM 场景。显式提交新规则才转换当前包。新旧字段不能同时修改，已经转换的包不能通过旧 scope 写入降回旧语义；普通元数据保存保持原规则。历史快照仍按旧规则与当前规则取交集，不能因配置转换扩大已有运行的权限。

旧 Trigger 未提供 enabled 时仍为 true。换绑使旧代次引用失效，求值时跳过这些条目。群聊白名单按剩余的人员和群类别取交集，空白名单仍拒绝。当前代次中身份或部门关系待核验的拒绝规则继续按原语义处理。旧引用可在同场景同名单侧保持用于显示/移除，跨场景或从黑名单移动到白名单必须重新验证。模板复制保留显式配置，按目标员工重新验证其引用；不会按名称重绑其他员工渠道身份。

此功能不改变员工使用范围、群共享、人工确认或业务资料授权。

自动化任务能力包仅支持「白名单」和「全部触发器 + 黑名单」。迁移 118 将旧混合规则中的黑名单从白名单减去，保留原有效授权。保存时不再接受同时携带两个名单。
