# Skill、插件与员工能力包迁移设计

状态：2026-11-17 资源/能力包管理已有实现，task 执行已接入固定 Skill 和静态认证远程 MCP。本文保留完整产品方案，替代此前员工直接绑定 Skill / Plugin、拍平旧能力包的设计。

## 官方资源与空间自建资源

Skill 和插件各自维护定义、版本和目录。官方资源对各空间可见，员工能力包绑定官方资源 ID，运行时按会话记录版本。空间自建资源仅供本空间使用。已有接口省略 `scope` 时只列出空间自建资源，员工配置和资源库显式请求 `scope=all`。

| 操作 | Skill | 插件 |
| --- | --- | --- |
| 官方目录、详情、版本历史 | `/official-skills` | `/official-plugins` |
| 空间目录、导入或创建、编辑 | `/workspaces/{w}/skills`、`/workspaces/{w}/skill-imports` | `/workspaces/{w}/plugins` |
| 管理本空间的绑定 | 资源详情下的 `GET /agents`、`POST /assign` | 同样的子路径，分配时允许稍后连接账号或发现工具 |
| 创建独立副本、归档私有资源 | `POST /copy`、`DELETE` 资源详情 | 同样的操作，仅复制插件定义 |

以上路径以 `/api/v1` 为前缀。平台管理员可以从自己有管理权的空间发布指定版本，向已有官方资源发布新版时须提交当前资源修订号。下架会从可选目录移除资源，既有绑定保留。停用会阻止后续使用。分配请求包含每个目标的员工、能力包和预期包版本，响应逐包报告成功、重复、冲突或待授权。权限和使用明细以目标空间为界。

迁移 `000077` 在已有 Skill、插件及版本表中使用空 `workspace_id` 表示官方归属。版本外键与归属触发器共同校验官方或同空间约束。能力包和员工插件账号保留工作区归属。官方 Skill 资产在 `official/skills/<skill_id>/versions/<version_id>/` 下按 manifest 保存。直接绑定只写数据库引用，手动复制才生成独立资产版本。远程 MCP 的定义在 PostgreSQL，凭据按空间共享或员工独享连接加密存储。裸 sbx 按任务快照获取 Skill 文件，插件工具调用沿用员工账号和逐次授权。

## 已确定的产品边界

- 员工绑定能力包，能力包包含 Skill 和插件操作，并配置分场景使用范围。工作区能力包是模板，复制给员工后独立维护，不随模板自动变更。
- 能力包只展示最新资源版本号。每个新会话、新任务在创建时确定使用的资源版本，后续执行沿用其快照。
- Skill 支持上传 ZIP 和指定 GitHub 仓库路径；保留 SKILL.md 及脚本、参考资料等完整目录，GitHub 导入记录实际 commit 与子路径。
- 插件定义在统一资源库，新绑定默认复用空间共享连接，管理员也可选择员工独享连接。同一员工多个能力包使用同一插件时，共用该员工的一份插件账号授权，新任务可以使用所选账号提供的全部工具。员工账号授权关系本身不授予工具使用权，必须另有获准能力包。认证状态与资源版本分别维护。
- Plugin 长期类型为 MCP / CLI，本批只做远程 MCP；CLI 与本地 stdio 暂不实现。OAuth 账号连接见[插件接入](platform-plugins.md)。
- 前端沿用现有组件、页面结构和 design token，不另起一套样式。未实现功能隐藏，不保留能产生假成功的 Mock 入口。

同一员工的插件账号发生换绑时，所有包含该插件的能力包在新配置中共用新账号；界面应说明影响哪些包。旧会话仍引用原账号，不能悄悄改换；密钥刷新不改变账号身份或插件版本。各能力包分别校验使用范围。选择空间来源的员工共用同一空间、同一插件固定版本的连接。

## 设计要点与约束

| 对照点 | 当前差异 | 设计约束 |
| --- | --- | --- |
| 能力包 | 能力包归员工；前端已有包配置 | 保留员工包及有效范围，工作区模板复制，不拍平授权 |
| Skill 内容 | 旧后端保存完整目录；新版前端已有 Git、ZIP、Markdown、手动入口，ZIP 已读取并解析，但最终保存仅元数据及正文，Git 拉取仍为 Mock | 保留现有交互，拟将四入口汇入完整目录版本管线；不能称前端只有 Prompt，也不能将解析成功当作完整资产已保存 |
| 版本 | 旧包保存 resourceIds，目录取当前资源；前端可选 latest；Kiko 规划显式升级 | 新会话和新任务使用最新资源版本，已有运行沿用快照 |
| MCP 与插件 | 旧后端只实现远程 Streamable HTTP；前端还有 SSE 等选项 | 本批明确远程 MCP 支持的协议，不能把前端选项当已实现；插件定义与授权分离 |
| 认证 | 旧 MCP 资源版本内封装凭据；前端端点和密钥同表单 | 定义、普通接入参数、PluginAuth 分离；账号授权发生在员工绑定流程 |
| 工具权限 | 旧执行合并按 serverRef + tool；前端 mcpTools 是裸名称 | 工具引用须包含 plugin_id 与 operation，防止不同插件同名工具串权 |
| 风险与沙箱 | 前端风险标签和网络/文件系统开关不等于执行保障 | 没有执行机制的能力隐藏；不可凭 Mock 风险等级自动授权 |

## 拟实施契约，不是已发布 API

最终操作、字段、错误与示例须在 `backend/contracts/openapi.yaml` 按 HTTP 设计完成评审后实现，以下给出资源和一致性要求，不预先发布 URL。

| 资源 | 必须表达的事实与操作 |
| --- | --- |
| Skill | 工作区、稳定标识、名称/说明、内容版本、digest、文件清单、来源；ZIP / GitHub 导入，拟接通现有 Markdown / 手动入口；列表、版本与内容查询、更新为新版本 |
| Plugin | 工作区统一定义、版本、远程 MCP 连接/参数声明、认证要求、工具结构；登记、查询、更新版本、检查接入条件 |
| 员工能力包 | 所属员工、名称/说明、启停、使用范围、Skill 与 Plugin 资源引用；创建、查询、并发编辑、模板复制 |
| PluginAuth | 所属插件和工作区、账号/目标、认证方式、凭据引用、状态；员工绑定流程发起或补齐授权、检查/更新/撤销；同一员工的多个能力包按插件共用所选连接 |

### 版本与保存

- 能力包名称和说明在任务提示词中的生效时点，以[任务提示词行为基线](../../docs/spec/task-package-prompt.md)为准，不等同于员工身份快照。
- 员工首次使用某个 Skill 或 MCP 时选用当时的最新版。该员工所有能力包共用同一资源版本。管理员在配置页手动升级后，新任务和已有任务的下一轮使用所选版本。已开始执行的一轮继续使用本轮快照。主聊天通过平台工具委派任务。
- 能力包可在连接账号或发现工具前保存。MCP 的可用工具由所选账号决定，配置页只读展示。每轮首次成功探测时记录完整清单，失败可以重试。运行时继续校验能力包授权、账号状态、上游工具名和 schema。
- 所有包及资源写操作使用现有乐观并发规则，避免模板复制、更新提示与编辑互相覆盖。包自身是否具有独立不可变版本和历史界面仍待确认。
- 升级接口为 `POST /api/v1/workspaces/{workspace_id}/agents/{agent_id}/capability-upgrades`。管理员提交 kind、resource_id、from_version_id 和 to_version_id，服务端在一个事务中核对最新版及目标版本的账号并更新全部引用。

### Skill 完整目录版本与导入方案（待实施评审）

- `skill_id` 是稳定资源身份，`version_id` 是服务端生成的不可变内容版本身份；展示版本标签不作绑定依据。一个版本对应整个目录，不只是 SKILL.md 正文或数据库里的版本号。
- 同一版本包含 `manifest.json` 和 `files/` 下完整 SKILL.md、脚本、参考资料及附件。manifest 的 `format_version` 表达格式版本，文件清单记录规范化路径、大小及 SHA-256；整体内容摘要用于完整性校验。更新发布新的 `versions/<version_id>/` 目录，旧目录不可覆盖。
- 新建与更新明确选择目标资源，不凭同名自动覆盖/追加另一资源。改展示名不改变内容版本；编辑正文须在原完整目录基础上发布新版本，保留其他文件。
- 拟保留并接通四入口：ZIP 读取完整包；公开 GitHub 按仓库/ref/子路径解析实际 commit；Markdown 粘贴生成单一 SKILL.md；手动通用字段生成标准 SKILL.md。四者使用同一后端校验和发布管线，不另造 Prompt 型 Skill。`.md` 文件上传是可选扩展，不能把现有粘贴入口称为已支持文件上传。
- ZIP 接受根目录 SKILL.md 或唯一外层目录，歧义报错；GitHub 目录 URL 归一为 repo/ref/subpath，不错误拆分含 `/` 的分支名。私有仓库和其他 Git 服务尚未纳入。
- 导入先产生绑定工作区与创建者的暂存引用 `import_id`，返回元数据、文件树与摘要预览；确认发布时重新鉴权并保存完整资产。不能把前端解析后的一段正文重新提交为完整 ZIP。长操作返回真实阶段与耗时，超时/取消不假成功。
- 展示名、Skill 技术名与版本标签分开；旧前端宽松 frontmatter 与标准字段之间明确校验/映射，不静默丢弃元数据。工具标签只作说明，不授予操作权限。
- 文件完整写入并校验后才将版本标记为可见，处理重复请求、并发发布、中断恢复及无引用暂存清理。S3 不提供目录事务，不依赖 rename。被历史版本/能力包引用的目录不得随意清理。

### MCP 定义、账号及能力包引用

- 资源库管理 Plugin 定义与版本，不保存员工业务 Token 或登录态；员工在能力包使用该插件时补齐账号授权。包引用员工选用的插件定义版本。
- 拟首版采用远程 Streamable HTTP、免认证及静态凭据；OAuth 授权码已接入裸环境，独立 SSE、CLI/本地 stdio 留待后续。协议支持范围与认证方式需最终评审后写入 OpenAPI。
- 有认证的 tools/list 探测在员工授权上下文中进行；可见工具受账号影响，不能将某账号返回的工具目录无条件视作所有员工都能用。定义版本与探测证据、账号动态状态分开，定义/地址/凭据变化使相应旧证据失效。
- 同一员工的多个包共用插件版本和账号来源。工具由该账号在轮次开始时发现，停用插件或撤销账号后立即阻止新的调用。
- 现阶段使用统一 `KIKO_AUTH_SECRET` 根密钥按用途派生插件凭据加密密钥；拟应用层加密后入 PostgreSQL，普通接口不回显秘密，不进入 Skill 目录、manifest、插件版本或执行快照。凭据字段、加密封装/密钥版本及轮换迁移在实现契约中细化，不能宣称当前 PluginAuth 已加密落库。
- 资源保存、账号授权有效、MCP 探测成功、能力包配置有效与 Engine 实际执行是不同结果。未实现执行链路前不显示“员工已可执行”。

### 能力包按场景授权

2026-11-19 已确认：单个包固定有私聊、群聊、触发器三个独立场景。先在顶部选择启用场景，再显示已启用场景对应的配置。包的总启停仍是外层开关；任一场景开关不能允许已停用的包。不会新增按渠道重复配置的权限矩阵，也不是任意多条规则组成的优先级列表。

网页新建、管理 MCP 新建、模板创建或系统发放 KIKO 助手时，在同一事务内创建一个启用的空能力包「基础能力」。私聊、群聊均继承员工使用范围且黑名单为空；触发器默认允许该员工的全部触发器且无排除项。该包可编辑，管理 MCP 按现有流程查询包 ID 和版本再添加 Skill 或 MCP，无需先到网页建包。模板预设能力包和 KIKO 助手内置体验包仍按原规则发放，与「基础能力」并存。已存在的员工不补发。不改变管理员工、资源绑定或运行时使用权限。

| 场景 | 可选身份 | 授权语义 |
| --- | --- | --- |
| 私聊 | 具体人员或适用渠道的部门 | 「继承员工使用范围＋黑名单」或「仅白名单」；私聊不能配置群。 |
| 群聊 | 具体人员、适用渠道的部门、员工所在/已发现的群 | 两种模式同私聊。黑名单任一命中即拒绝；白名单中人/部门为一类，群为另一类，同时配置时两类都须命中，仅配一类只判断该类。纯白名单不带黑名单，空白名单不授权。 |
| 触发器 | 当前员工的具体定时任务或 Hook | 沿用已有触发器范围和拒绝优先规则，只增加场景启停，不用人员或群名单替代触发器身份。 |

场景来自可信运行来源，不取客户端/模型自报来源。部门沿用可信目录的包含子部门规则，企微无部门选择，未知不授予白名单权限；已有黑名单无法可靠排除时保守拒绝。群引用匹配真实会话的绑定、代次与稳定群身份，群话题按所属群判定，不从名称推断身份。配置不授予加入群、读取群历史或访问外部资源的权限。

先验证员工/业务入口准入，再判断每个包。有效范围以任务原包授权与包当前授权的交集为准；后补授权不得扩张在途任务，撤权阻止后续调用。多个包各自判断后才合并实际工具，不把「甲在一群」和「乙在二群」拆成两份集合交叉组合。一个包不匹配，不会否决其他实际满足条件的包。工具调用沿用本轮选定的插件版本，并校验账号、工具名和 Schema 摘要。

旧包和旧在途快照继续按原人员/部门范围求值；新配置单独记录场景，不能把旧白名单＋黑名单自动转成纯白名单而丢失拒绝。工作区模板不携带员工的联系人、真实群或触发器专属授权，模板复制须遵循现有的凭据/引用边界。无完整事项交接链之前不新增交接场景。

验收应独立覆盖：两个聊天场景及触发来源互不放行、相同人员切换群、同群更换人员、人群交集、不同渠道同名身份、部门快照缺失、场景禁用和在途撤权、旧格式与新格式并存。

### 导入和探测

- ZIP 验证路径穿越、链接、解压大小、数量、重复路径及 SKILL.md；保存完整文件清单与哈希，导入时不执行脚本。
- GitHub 路径解析为仓库、ref、子路径，解析实际 commit 后读取固定内容；不执行仓库 hooks、过滤器或安装命令。私有仓库及其授权未定，不因本机已有登录态自动纳入支持。
- 远程 MCP 连接和 tools/list 必须有真实结果；地址与凭据改变使旧探测失效。适用 SSRF、重定向、超时、响应体及工具 schema 限制。
- 普通查询不返回秘密，Token 不放进插件版本、Skill、日志或配置快照。未授权、授权失效与服务不可达分别展示。

## Skill 资产存储

Platform 当前负责导入、不可变版本发布和文件访问授权，使用本地或 S3 资产后端。正式版本按逻辑 key、存储身份和清单读取。配置和备份见[统一存储配置](../../docs/architecture/storage-configuration.md)。

工作区发布与模板生成的正式版本统一写入 `workspaces/<W>/skills/<skill_id>/versions/<version_id>/`。直接绑定官方版本继续复用引用。此次开发环境切换允许旧自定义资产缺失，对应绑定显示为不可用。

Skill 导入材料按导入 ID 保存在 `<root>/temp/uploads/skill-imports/<W>/<import_id>/`，发布或导入过期后回收对应材料。Engine 依现有授权结果将 Session 加载名链接到固定版本的 `files/`。隔离沙箱同路径只读挂载官方和当前工作区两个 Skill 目录。筛选、升级与撤权另行设计。[Skill 目录与挂载](../../docs/architecture/storage-paths.md#skill-版本目录与沙箱)

## 实施前待确认

1. **能力包自身的版本。** 能力包有并发 `version`，任务快照记包 id/version；这不是工作区共享包的发布版本。员工包独立维护，执行快照固定资源版本，先不加包发布/自动升级体系；独立不可变包历史与回滚是否需要仍待确认。
2. **同员工多包引用同一资源。** 首次绑定后共用员工所选版本，升级时一起更新。
3. **认证与导入扩展。** 裸环境已接入免认证、静态凭据和 OAuth 授权码。GitHub 私有仓库、其他 Git 服务和 CLI 登录另行设计。

## 验收计划与交付边界

设计确认后依次做资源导入与版本、员工包绑定与范围、账号授权与 MCP 探测，再接运行时。每阶段分别记录配置已实现、真实 HTTP/数据库已验、浏览器已验、实际执行已验，不把资源保存当作工具可执行。

重点覆盖：四入口统一发布（以最终确认范围为准）、完整附件更新不丢失、Skill 各版本目录不可变、Docker 重建持久化、本地/S3 同一内容互读及故障不回退；ZIP 完整目录和恶意路径；GitHub ref/子路径/commit；新会话使用最新与旧会话快照保持稳定；模板复制后独立；跨工作区引用拒绝；并发保存冲突；包权限与来源配对；多个插件同名工具；同员工多个包共用账号并分别核对使用范围、不同员工不自动共用账号、账号存在但没有可用包时不得执行；账号秘密不回显；探测失效/超时；未实现入口隐藏；复用现有 UI token。

本次仅文档核查，未改产品代码、OpenAPI 或数据库，未运行新测试。

### 飞书运行主体与能力包范围

渠道运行使用独立 `manager_channel_principals`，不创建 Web 账号、不把渠道用户关联成工作区 owner。Manager 从已授权的运行配置/输入记录重建 `ChannelExecution`（principal、conversation、connection generation、input），Platform 仅在运行专用方法识别此上下文；普通资源管理接口仍要求 Web 成员权限。上下文本身不构成授权。

模型密钥、Skill、Plugin 账号与文件读取在每个短事务内重新验证工作区、绑定/租户/连接代次、员工启用、当前渠道使用范围及正在运行的 Input/Turn、准入 epoch 和停止版本；外部存储/探测后再次核验。创建任务的能力快照允许尚未创建 Input，但仍核验同一渠道主体及 Conversation 准入。缺身份、旧代次、未确认租户、撤权、已停止输入均默认拒绝，不退回 owner 代权。

能力包新增 `allow/deny` 人员与部门引用，`mode` 仍为继承+黑名单或白名单+黑名单；群引用不进入人员能力包范围。Web 使用工作区账号，飞书/钉钉使用绑定与 epoch 限定的真人/部门，企微只能使用已验证映射的回调身份，不能用搜索 ID 授权，也不支持部门。模板包不能包含具体员工的渠道身份。

保存新增引用时在事务内复验当前来源。既有失效引用可保留供展示/删除，不自动换绑；元数据/停用不因旧引用失效而被阻断。运行时先校验员工准入，再独立计算原包快照与同一包当前规则，任何一侧拒绝即移除该包；不将不同包的名单拍平，后续新增资源不扩张旧快照。部门匹配沿用现有目录函数，未知黑名单匹配拒绝、未知白名单不授权；不更改既有 unknown 用户语义。

旧 `allow_member_ids/deny_member_ids` 为 Web 兼容字段，不解释为渠道 ID；仅旧字段的渠道执行保留原先保守限制。新界面明确转为 Web 类型化引用后，可与其他渠道名单混选，按各自身份匹配。Trigger 独立 `trigger_scope` 不受人类名单改造影响，仍按原触发器权限验证。
