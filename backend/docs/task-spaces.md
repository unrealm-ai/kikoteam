# TaskSpace：任务归属、业务分组与独立执行环境

状态：2026-11-18，用户已授权，`feat/taskspace` 实施中。本文区分已确认语义、本轮底座和后续业务，不表示公开 API、数据库、Engine 或端到端验收已经完成。普通 Conversation 任务继续采用[原生命周期](../../docs/architecture/conversation-lifecycle.md)；本轮新增另一种任务归属，不把旧路径偷偷改成 TaskSpace。

## 目标与范围

Task 的业务归属为 Conversation 或 TaskSpace，二者互斥。Conversation 不创建 TaskSpace 任务，也不为建立聊天创建空间或占位任务。普通聊天委派仍保留原 Conversation、来源与环境关系；不得伪造 Conversation 来容纳无会话来源的空间任务。

TaskSpace 是工作区内持续的业务任务分组，不是聊天 Session、执行任务或共享文件系统。一个空间包含多个 Task；空间任务各自拥有独立 Pi Session、沙箱身份与目录。复用空间不复用其他任务的工具授权、凭据、运行进程或原生历史。普通 Conversation 内任务的既有共享环境不属于此次独立环境改造范围。裸环境下独立目录和身份不等于操作系统安全沙箱，不能据此宣称任意文件访问已被隔离。

本轮实施任务归属、业务 key、空间任务创建与查询/授权、独立执行环境及必要契约。定时任务、Webhook、事项交接/验收、资料共享和人工确认均为后续接入者，不因此视为本轮已交付。

## 业务 key、事件幂等与授权

- 非空 `businessKey` 在同一 workspace 内唯一，对应一个 TaskSpace。不同员工不能各自创建同工作区同 key 的另一个空间；不同 workspace 的同 key 不关联。
- 业务 key 用于分组，事件 ID/请求幂等键用于防止重复受理。同 key 的不同事件可以创建不同 Task；同一受理重试不得重复创建 Task 或无 key 空间。
- 有 key 时原子查找或创建；并发竞争只能得到同一空间。无 key 时创建独立随机空间，仍须被创建事件的幂等事务约束，不能把全部无 key 请求聚合为空字符串空间。
- 知道 key、Space ID、Task ID 或展示名称不构成访问权。空间命中后必须校验当前主体及目标员工权限；不得以另建同 key 空间规避拒绝，也不得泄露已存在空间内容。
- 空间归属、任务来源和回告目标分别记录。没有来源 chat 的任务不得假造 chat，也不得因共用空间自动向其他任务的来源会话回告。
- 读取列表、详情、Input、Turn、原生记录引用、SSE、停止/补充及重试都须应用对应空间授权，不能只在创建时检查。管理员角色不得被无意作为所有私有上下文的读取旁路。

新数据库无需旧业务配置兼容，但唯一约束、事务回滚、重复提交、并发冲突及故障恢复仍是本轮必需能力。具体字段、错误码和公开路径以实现后的机器契约为准，本文不提前固定尚未确定的 owner schema。

## 后续事项接入约束

同一事项的接手、继续交接和整改任务进入独立的事项 TaskSpace。原 Task 留在原 Conversation 或 TaskSpace，并在原 Session 开新 Turn 验收。通过事项关联及明确发布的业务信息连接来源，不把原会话或原空间全量历史自动披露给接收员工。建议事项业务键为 `workitem-<ID>`，名称本身不授予空间权限，外部提供的字符串不能冒充服务器事项关联。

businessKey 只是同工作区触发历史分组，不能直接当作跨员工空间授权。后续事项需另外维护 Assignment、当前负责人/版本、目标授权、安全交接边界及派发幂等；每个 Task 的环境仍独立。本文不假定共享文件、实时共享正在生成的工具日志或原 Task 的环境搬迁。

## 现有 API 需核对的变更面

实施前现状如下，不能据此把新能力标为已可用：

- `POST /sessions` 仅以 `conversation_id + mode` 创建，普通委派也复用此路径；空间任务必须有明确受理路径和互斥归属校验。
- Task 查询复用 Session/Conversation 可见性和筛选，必须补空间路径，避免 INNER JOIN 导致空间任务消失或放宽整个查询泄露旧私聊。
- Task 来源目前为聊天委派或未指定，空间归属不能替代来源；回告继续依赖明确来源与目标授权。
- 环境分配、Engine 领取、配置解析、工具授权、暂停/停止/归档和回收目前依赖 Conversation，必须逐一检查空间任务及任务级环境，不能仅扩展创建 DTO。
- 所有新增公开请求保持当前认证、CSRF 和字段白名单，不接受客户端自报系统来源、授权凭据、环境路径或回告目标来扩大权限。

## 验收矩阵与依赖

| 范围 | 必验行为 |
| --- | --- |
| 归属约束 | Task/Session 只关联一种业务归属；两者同时提供、两者缺失、chat 模式挂空间均被拒绝；普通委派不产生空间 |
| key 与幂等 | 同 workspace 同 key 并发只建一空间；不同事件产生不同 Task；同事件重试仅一 Task；无 key 重试不多建空间；跨 workspace 同 key 隔离 |
| 权限 | 跨员工同 key 不自动获权；列表/详情/SSE/控制一致；撤权和重试重新裁决；任意 ID/展示名不能串空间 |
| 独立环境 | 同空间两个 Task 的 Session、Pi 历史、环境 ID、目录不同；停止/归档 A 不停止 B；重启 A 保持其自身身份，不借 B 环境 |
| 来源与回告 | 同空间不同来源保持独立；无 chat 来源不生成聊天回告；目标撤权后禁止新的披露；受理不等于外部送达 |
| 现有路径 | Conversation chat/委派、私聊可见性、群成员校验及普通任务共享环境不回归 |
| 故障恢复 | 空间/任务/初始 Input/派发意图原子提交；提交成功但响应丢失可恢复；未知执行结果不因空间重用被盲重放 |
| 生命周期 | 仅按目标任务收尾和回收其空间任务环境；保留文件/历史，不暗中递归删除；无环境时不启动环境只为清理 |

依赖顺序：归属与授权模型 → 原子受理及查询 → Engine/Runner 环境与权限 → 来源/回告兼容 → OpenAPI 与端到端验收。人工确认 FIFO、触发调度和事项状态机不作为本轮底座完成的替代证据。

## 本轮公开契约与实现边界

机器契约见 [TaskSpace](../contracts/modules/manager/task-spaces.yaml) 和 [Session](../contracts/modules/manager/sessions.yaml)。当前实现已落盘、整体验收进行中，不代表已部署。

- `GET/POST /api/v1/workspaces/{workspace_id}/task-spaces`：列表游标绑定当前用户/工作区，默认 20、最多 100，按 created_at/id 倒序；列表 agents 为空，详情读取授权。创建要求 `Idempotency-Key`、`agent_id`，可选 `business_key`；key 须非空无首尾空白、最多 200 字，省略或 null 表示独立空间。相同请求重放返回 200，否则 201。创建空间不创建 Task。
- `GET /task-spaces/{task_space_id}`：当前有效工作区成员且为该空间 created_by 才可读取；工作区管理员不自动获得他人的空间。
- `PUT /task-spaces/{task_space_id}/agents/{agent_id}`：仅创建人显式修改员工授权，提交字符串 `version` 和 `enabled`；添加须满足当前员工使用范围。撤回在事务内关闭准入并发起相关任务 stop，不表示运行进程已经停止。重新加入通过 admission_epoch 隔断旧任务，不能复活其权限。
- 相同 business key 的查找不会隐式新增第二名员工授权；已有空间所属用户不同不得读取或接管。同一所有者需先显式授权第二名员工，再创建其空间任务。
- `POST /sessions` 支持 `task_space_id + agent_id + mode=task + input`；与 conversation_id 互斥，空间任务不接受省略首条输入的空创建。首条输入要求幂等键；当前 owner、员工使用权和空间授权均重新校验。
- Task/Session 响应的 `conversation_id` 与 `task_space_id` 互斥，非所属字段省略，不输出空字符串假 UUID；两类列表增加 task_space_id 筛选。空间任务仍复用现有 Input/Turn/Session 操作与读权限，不能凭工具或查询绕过归属。
- 内部 Harness/Sandbox 携带真实 task_space_id/task_id；Sandbox 为 conversation_id 或 task_space_id+task_id 双 owner 互斥。普通会话 Sandbox 继续共享，空间任务各有独立 Sandbox。

本轮无资料共享、事项交接、定时/Webhook 和人工确认，也不为无 chat 来源的空间任务新增回告目的地。来源查询与既有回告保持独立，不把共同 space 解释成共同通知受众。

## 执行 Agent 读取同空间任务与语义摘要

**2026-11-20 已确认目标，当前改造中，尚不代表本轮测试或部署完成。** 本节替代此前“只读同一触发器任务”和“返回助手正文及事件过程”的历史查询设计。已有 `list/get` 工具保留，收紧返回内容，并增加同一私有 MCP 内的摘要写入工具。精确字段、长度限制与分页以同步更新后的 [MCP 契约](../contracts/taskspacehistory/tools.json) 为准。

### 默认共享范围与授权

- 执行任务默认可以查询**同一个实际 workspace + TaskSpace** 内其他任务的进度事实和已发布语义摘要。不同 trigger ID、触发类型或来源员工不再构成同空间内的额外过滤条件；不另设管理员维护的共享 ACL，也不要求逐项批准共享。
- “实际 TaskSpace”按服务器任务归属判断，不按名称、业务 key 字面值、来源描述或调用者提供的空间 ID 推断。不同 workspace 或不同 TaskSpace 始终隔离；仅知道 Task ID 不产生读取权。
- 事项接手、继续交接和整改任务按各自实际事项 TaskSpace 参与共享。原任务仍留在原 Conversation 或原 TaskSpace；存在事项关联不意味着原任务可以跨空间读取全部任务，验收关联也不改变这个边界。
- 默认共享不豁免源执行身份验证。每次工具调用仍核验当前执行者的 Input 授权、Session/Engine/assignment/generation、执行窗口和空间有效性；员工或来源权限撤回后不能凭旧工具凭据继续读写。
- 本规则只改变执行 Agent 的受限同空间摘要接口，不改变手动空间创建/员工授权、公开 Task/Session API、浏览器成员可见性或管理权限。管理员不因此获得私有任务原文读取权。

### 工具与返回内容

Pi 直连 Manager 的 `/mcp/task-space-history`。Engine 仅为 `mode=task` 且归属 TaskSpace 的 Session 挂载，使用专用 Bearer 和 `X-Kiko-Task-Space-Input`，拒绝 Cookie 和 Origin。

| 工具 | 行为边界 |
| --- | --- |
| `task_space_history_list_tasks` | 保留现有列表工具，按任务创建时间和 ID 倒序分页，返回任务身份和当前进度事实。默认 20、最多 100；目标仅限同一实际空间。 |
| `task_space_history_get_task` | 保留现有详情工具，返回目标任务的状态/进度事实及存在时的显式语义摘要。不得返回原始 Input、Turn 内容、事件流、助手原话、工具参数或输出、附件及原生记录。旧事件正文分页不再作为共享内容提供。 |
| `task_space_history_save_summary` | 新增私有写工具。当前任务在已有 Turn 内为**自己**登记有界的语义进展或结果摘要，归属由可信当前 Input/Turn 推导；不得选择别的任务、空间或 Turn 代写。不另起模型调用或后台总结任务。 |

语义摘要是任务主动组织的业务概述，不是对助手原文机械截断或改字段名。共享读取不回退到 `manager_turns.result_summary`，因为该字段可能保存助手原话；没有显式摘要时只返回进度事实和摘要缺失状态，不虚构摘要或回填原文。摘要仍是不可信业务资料，不构成新的指令、授权或工具调用依据。

结果摘要只有在其所属 Turn **成功结束**后才可对同空间其他任务展示。写入工具返回成功仅表示摘要已登记，不表示 Turn 成功、结果已发布或整个业务任务完成。失败、取消、未知或仍在执行中的 Turn 不得仅凭候选结果摘要对外宣称成功；进展摘要必须明确区别于结果摘要，不能冒充成功结论。任何摘要均受服务端长度和内容字段边界约束，工具不支持原文、事件、附件或凭据上传。

### 不随此改造改变的行为

- 不自动注入其他任务的完整历史；由模型按需调用已有查询工具。各任务的 Pi 原生 Session、目录、沙箱、工具权限与凭据继续独立。
- business key 仍只用于同工作区空间分组，事件幂等仍独立；同空间共享不改变创建任务、继续任务或接手任务的授权。
- **群通知与回告完全不变**：不新增目标，不扩大群受众，不把同空间摘要自动广播到其他任务来源群，不改变发送事实、unknown 或送达后上下文处理。

### 本次验收要求

1. 同空间不同 trigger ID/type、手动/系统来源任务可查询受限事实和已发布摘要；跨 workspace、跨实际空间不可见。
2. 原任务未搬入事项空间时，不因 handoff 关联绕过空间边界；接手任务只按实际所属空间查询。
3. 保存摘要不能指定其他任务或 Turn；旧 Input、失效执行代次、撤权及已结束执行窗口被拒绝。
4. `get` 不泄露助手原文、原始 Turn/事件、工具载荷和附件；缺摘要不回退 `result_summary`。候选结果在成功 Turn 前不可见，失败/未知结果不冒充发布成功。
5. 列表/详情分页和当前进度保持真实；公开 API、管理员权限和群通知回归不变。测试通过范围另记，不以本节目标代替验收证据。

## 系统入口授权目标（用户已确认，尚未开发）

以下规则用于未来事项交接、定时任务与 Hook，不表示本轮已有入口，也不改变当前手动 TaskSpace API 的创建人权限和显式员工授权规则。系统入口接入后默认不要求用户先手动为目标员工添加空间授权；由可信业务受理链路校验其入口权限并建立必要的空间任务关联，不能将该默认行为推广到任意客户端或仅持有 businessKey 的调用者。

| 入口 | 员工使用范围 | 能力包选择 |
| --- | --- | --- |
| 事项交接 | 默认允许所有来源 AI 员工交接，可按来源员工限制；身份限定在获准工作区和当前有效员工，不是人类用户名单 | 取接收员工自己的能力包。每包可继承该员工的交接使用范围，或按来源员工黑白名单细分；不继承发送员工全部能力 |
| 定时任务 / Hook | 默认可信、启用且与目标员工绑定的触发器可调用，不走人类使用名单；仍校验触发器身份、绑定版本和允许动作 | 每包可按具体 trigger ID 黑白名单筛选；未限制时使用该员工启用的包，不因触发器可信而绕过包限制 |
| 事项验收 | 使用事项和提交的可信关联恢复原始发起员工的原 Task 和 Session | 不扩大根任务的原始授权上限；重新校验原包及资源当前有效性，不承接后续处理员工的权限或悄悄升级为全部新包 |

“继承交接使用范围”指继承接收员工对来源员工的准入，不是空间成员授权的人工配置，也不是沿袭来源任务的凭据。人员、来源 AI 员工、trigger ID 是不同主体类型，不能按同名合并或混用黑白名单。空间分组与入口权限、能力包权限仍分别裁决。

selectionMode 的 all/allowlist/denylist 是选中模式，不能把其保存的所有列表机械叠加；新 UI/契约的精确字段与组合规则在实现入口时确定，本文不额外增加一套未经确认的手动空间审批。
