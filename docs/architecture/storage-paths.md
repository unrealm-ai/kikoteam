# 文件路径、业务会话与隔离约束

**本地磁盘布局（2026-11-24）** 本轮在本地磁盘上统一文件路径。Pi 继续写原生 JSONL，Runner 继续使用 SQLite，项目上传保留文件回执和同卷原子发布。现行二进制的配置见[统一存储配置](storage-configuration.md)。

## 1. 关系与术语

```text
Workspace
  ├─ 工作区共享资源（Skill、插件非秘密资产、显式共享资料）
  └─ AI 员工 Employee
       ├─ 显式共享给该员工的记忆/资料
       └─ 业务会话 Conversation
            ├─ 对话执行 Session（chat）：独立模型上下文
            ├─ 本会话触发的任务 Task
            │    └─ 唯一执行 Session（task）：独立 Pi 原生上下文及 Engine 身份映射
            ├─ 会话共享 Sandbox / 工作文件
            └─ 会话记忆：从获准对话及任务结果中抽取
```

- 不另建“Agent 主体”层。文档中的 `chat/task Agent` 仅指执行角色。现有代码/API 的 `agent_id` 是 AI 员工的历史技术字段，不能据此再造 agents 路径；后续接口/表字段重命名需单独迁移，不在本次改已有 SQL。
- `conversation_id` 标识业务上的持续交流/处理范围；`session_id` 标识一份执行上下文。多个执行 Session/任务关联同一业务会话，不能仅因为模型进程重建或执行重试就新建业务会话。
- Session 内仍按既有 Input/Turn 规则串行，多个任务可并发；业务会话共享工作盘不要求不同任务共用模型历史。chat 的后台压缩和静默追加仍只操作对应执行上下文。
- 同一业务会话及其触发的多个任务复用该业务会话的共享 Sandbox。chat 自身不申请/启动 Sandbox、不开放本地工具；任务首次需要执行环境时创建或取得业务会话 Sandbox，后续任务复用。共享不意味着把 Sandbox 工具暴露给 chat。
- 不同业务会话默认不共享 Sandbox。将记忆显式共享给其他会话或整个员工，不代表也共享工作盘、执行历史、账号或全部输入文件。

完整关系及创建、停止、归档和回收职责见[业务会话与共享环境生命周期](conversation-lifecycle.md)。Backend 创建业务对象、唯一环境登记及管理者分配；Engine 管物理环境，Runner 管内部进程。首版同一业务会话的 task Session 固定到同一管理 Engine/宿主；活跃业务会话不自动回收共享环境。

## 2. 统一逻辑 key 与物理根

`<root>` 表示进程看到的 `KIKO_STORAGE_LOCAL_ROOT`，`W` 是工作区 ID，`P` 是项目标识，`sid` 是平台执行 Session ID。各启动方式的默认值如下。

| 启动方式 | 持久化根 `<root>` | Session Skill 入口 | Engine 私有临时目录 |
| --- | --- | --- | --- |
| Mac 原生 Engine | `~/.kiko` | `~/Library/Caches/Kiko/context/<sid>/skills/` | `~/Library/Caches/Kiko/temp/` |
| Mac 通过 `./start.sh` 跑容器 | 容器内 `/mnt/kikoteam`，宿主机默认绑定 `~/.kiko` | `/mnt/context/<sid>/skills/` | `/var/tmp/kikoteam/temp/` |
| Linux 容器部署 | `/mnt/kikoteam`，绑定宿主机本地磁盘 | `/mnt/context/<sid>/skills/` | `/var/tmp/kikoteam/temp/` |

Mac 原生进程使用展开的绝对路径。Backend、Engine 和 Runner 按同一个持久化根解析其负责的文件。容器的 `/mnt/kikoteam/temp/` 位于挂载盘，存有跨进程使用的上传回执和实例锁。Engine 将 `runner.json`、Pi 运行配置和执行凭据写入节点临时盘。Runner 在本机 `/tmp` 下创建权限为 `0700` 的 `kr-…` 目录，在各 Session 的 `b-…` 子目录存放 `launch.json`、管理 socket 和 Bash 控制 socket。这样 Engine 临时目录的长度不会影响 Unix socket。Pi 将 cwd 写进历史，因此每次恢复都在节点临时盘上重建相同的 Session 工作目录。镜像通过 `KIKO_CONTEXT_ROOT` 和 `KIKO_RUNTIME_TEMP_ROOT` 指定表中两处节点路径。

```text
<root>/
├── official/skills/<skill_id>/versions/<version_id>/
│   ├── manifest.json
│   └── files/SKILL.md
├── workspaces/<W>/
│   ├── skills/<skill_id>/versions/<version_id>/
│   │   ├── manifest.json
│   │   └── files/SKILL.md
│   ├── work-files/<sha256>
│   ├── projects/<P>/
│   │   └── uploads/
│   └── sessions/<sid>/
│       ├── pi/
│       │   ├── sessions/*.jsonl
│       │   ├── session.json
│       │   └── input-receipts/
│       └── runner/
│           ├── token
│           └── processes/
│               ├── processes.sqlite
│               └── initialized
└── temp/
    ├── uploads/
    └── runtime/
        └── <engine_instance_id>.lock
```

Skill 的 `files/` 保存固定版本的完整内容，包括入口 `SKILL.md`、脚本和参考资料。工作区直接绑定官方版本时只保存引用。日常编辑使用 `projects/<P>/`，显式交付时才将当时的字节写入 `work-files/<sha256>`，由数据库记录名称、来源、摘要和交付关系。

主会话和任务各自使用 `pi/` 中的原生历史、身份映射和输入回执。首次使用 Runner 时才创建 `runner/`，固定 Token、进程账本及初始化标记随 Session 保留。Engine 在 `temp/runtime/` 创建并持有实例锁，Backend 在同一文件上核对接管条件。挂载盘须支持文件锁、SQLite 事务、同步写入和同卷排他重命名。`temp/` 中的文件按各自生命周期清理，运行中不得整体清空。

### 资产归属与引用

普通附件保留在项目，任务或事项可显式发布固定文件版本。远程 MCP 定义和凭据由 Backend 管理。共享资料与记忆由相应业务设计定义发布和可见范围。文件归属采用服务端稳定 ID，原文件名、来源、授权范围和关联的任务、Session、Turn 由业务记录维护。

### Skill 版本目录与沙箱

Engine 沿用现有 Skill 选择与授权结果，在节点本地建立每个 Session 的加载入口。每个加载名软链接到对应正式版本的 `files/`。Pi 通过一个 `--skill` 参数读取该 Session 的 `skills/`。裸沙箱直接解析这些路径。隔离沙箱从持久化根获得两项目录挂载，均为只读，源和目标使用与 Engine 相同的绝对路径。

| Engine 可见的源 | 容器 Sandbox 内目标 |
| --- | --- |
| `/mnt/kikoteam/official/skills/` | `/mnt/kikoteam/official/skills/` |
| `/mnt/kikoteam/workspaces/<W>/skills/` | `/mnt/kikoteam/workspaces/<W>/skills/` |

其中 `W` 限定为当前工作区。Session 本地入口也要在 Pi 和沙箱内同路径可见，例如 `/mnt/context/<sid>/skills/sales-report` 指向 `/mnt/kikoteam/workspaces/<W>/skills/<id>/versions/<version>/files/`。共享沙箱须能解析后加入任务的入口。Mac 原生模式使用展开后的对应路径。Session 链接可按固定版本引用重建，在 Pi 和仍引用它的后台进程退出后回收。筛选、同名取舍、升级与撤权留给 Skill 使用专项。

## 3. 会话记忆的共享方式

1. 记忆从业务会话内获准的对话、任务输入与结果抽取，保留来源文件/消息/任务和授权范围。原生执行上下文及其摘要不自动成为可共享记忆。
2. 一个会话的记忆可显式授权给多个指定业务会话，或共享给整个 AI 员工；共享以 DB 中的记忆范围/读者关联表达，**仍引用原会话的权威版本**，不靠复制到多个目录实现同步。
3. “整个 AI 员工”是共享目标范围，不等于该员工所有使用者/群都能读。检索必须同时满足共享范围、当前访问主体权限和来源限制；记忆不能绕过私聊、群聊或任务授权。
4. 不为执行 Session 新建 memory 目录；跨任务检索读同一业务会话记忆中自己有权访问的内容。多个抽取任务并发更新时按 revision/CAS 提交，不能相互覆盖；重复材料按来源身份去重。
5. 共享不授予写源记忆的权限，不自动扩大沙箱/文件/插件账号权限。明确需要独立副本时新建身份并记录来源，不默认为复制模式。
6. 撤权/删除来源时同步处理检索索引、派生摘要和缓存可见性；不能只隐藏原文仍从记忆泄露。向量或结构化索引可以在 DB/专用存储，目录只保存文件型正文/版本，不强迫全部记忆文件化。
7. 本次确定最小业务会话粒度和显式共享范围；抽取模型、触发时机、保留期限与冲突合并算法尚未决定。工作区范围的“全员记忆共享”也不因工作区共享资源目录而自动启用。

## 4. Hook、定时触发与业务 key

Hook/定时任务由业务配置定义 **business key 的提取或生成规则**，决定事件落在哪个业务会话；不能按每次 HTTP 请求或调度执行新建一个隔离会话，也不能把所有触发统一塞到员工的唯一会话。

- 在工作区、AI 员工、业务命名空间/触发规则范围内解析 key，并映射到服务端 conversation_id。不同规则是否共用命名空间要显式配置，不能因同字符串 key 自动合流。
- 原始 key 可以包含业务敏感标识，只保存于受保护的路由元信息，不直接写入对象路径、公开 URL 或普通日志；路径只用 conversation_id。哈希编码只解决命名，不代替访问控制。
- 同范围同 key 的并发到达须由事务/唯一约束裁决为同一业务会话；事件自身的幂等 ID 与 conversation key 分开，避免“同会话”误等于“重复事件”。
- 解析后仍验证员工、来源身份、目标会话、权限边界及生命周期；不能通过自填 key 访问别人的会话。
- **待业务规则明确**：key 缺失/空值/提取失败时拒绝、等待修正还是创建独立会话；冲突 key 与不同安全域如何处理；已归档会话遇新事件是拒绝、开新代还是其他策略；规则修改后的旧映射如何迁移。实现前必须有显式策略与测试，不能默认合并、复活归档会话或随机分流。策略未配置时不得静默路由到现有共享数据，应返回可诊断的路由未就绪结果。

## 5. 共享沙箱与本机目录

项目归属和平台 `sid` 分别决定稳定路径。普通业务会话的主对话与它派出的任务共用 `P = conv-<conversation_id>`，各自保留独立执行历史。TaskSpace 中的独立任务使用 `P = task-<task_id>`。项目可在首次上传时先于 Session 和 Runner 创建。前端、消息历史和工具使用相对项目根的文件引用。

普通会话内多个任务可共享文件，并发修改时协调写入者。归档单个任务只收尾其执行资源。父会话归档后，Backend 核验各 Session 停稳再回收共享环境，项目和原生历史按各自保留规则处理。任务空间内只收尾该任务的环境。首次创建才初始化工作盘，恢复时缺少项目或执行证据须报告实际状态。

### 上传、发布和回执

1. Backend 在 `<root>/temp/uploads/projects/` 保存项目上传的 `payload` 和文件回执。接收完整并核验准入后，在同一文件系统上排他原子重命名到项目的 `uploads/` 或用户指定的子目录。同名文件按现有规则选新名称。
2. 回执继续记录请求指纹和候选相对路径。发布完成后保留回执，重启或响应丢失时以原键重试返回首次结果，同键不同内容报冲突。Web 和渠道的附件预留、授权及投递状态沿用现有业务流程。[异步附件规范](../spec/async-inbound-attachments.md)
3. Skill 导入预览材料使用 `temp/uploads/skill-imports/<W>/<import_id>/`，与项目上传按用途和导入 ID 区分。仅回收对应导入的材料，发布或导入有效期届满后清理，当前有效期为一小时。

Backend 管理 Sandbox 登记、管理 Engine 及获准参与的 Session。环境代次与每个 Session 的分配代次分别核验，重复准备复用已登记的环境。裸沙箱的工具仍按宿主账号权限执行。各 Session 独立核验工具 Token、执行窗口与授权，项目共享不会扩大可调用的工具范围。

- 后台命令归执行 Session，保留 origin_turn_id，允许跨正常 Turn 存活；对话 idle 与后台进程数分别展示。有后台进程时首版保留其运行实例和环境引用，不能仅凭 Turn 完成回收。stop/归档即使没有活动 Turn 也要按所属 Session 收尾。
- Sandbox 工具 Token 随环境生命周期固定，换 Turn/进程重启不轮换。同 Session/同授权范围的 builtin 和代理入口可共用，其他 Session/范围独立绑定；管理和配置领取凭据分开。固定凭据不替代当前授权、执行窗口和旧进程退出核对。
- chat 不创建或直接操作 Sandbox，但后续任务可以使用已经存在的同一会话环境；Engine 侧原生历史始终独立保存，不把 Sandbox 快照当模型上下文。

## 6. 安全、发布、删除与恢复

- 平台资产/元数据接口按已验证的 workspace/employee/conversation/task/session 生成归属路径，拒绝穿越和跨资源访问；这不限制裸 Sandbox 工具的系统权限，工具工作目录不是 chroot。客户端传 ID 不等于获得平台资源权限。
- 对象源默认私有；禁止永久公开 URL、任意目录列表和高权限存储凭据下发。账号/Token/密钥不进入 key、manifest、Skill 或记忆，持久凭据走受保护存储，运行配置不作为公开资产或历史事件。
- 不可变对象先校验发布，再原子提交 DB 引用；数据库和存储无共同事务，须处理中断、重试、旧代次写入与孤儿清理。多文件版本由 manifest/DB 发布状态界定，不假设 S3 支持目录 rename。
- Pi 原生历史由 Pi 持久化，身份映射由 Engine 保存；平台只保存位置和身份，不增加检查点包或上传提交屏障。公开消息和可靠事件仍以 DB 为准，原生历史供模型上下文加载，两者无跨存储原子提交承诺；压缩和静默追加遵守各自 Session 的单写者顺序。故障后旧 Turn interrupted，新 Input 经 `--session` 加载并继续，不自动重发旧 prompt。
- 运行/缓存/tmp 清理不得删除引用中的持久资产。共享 Sandbox 回收不删除会话记忆、历史产物或 PluginAuth；删除员工不级联清除仍有引用的工作区资源。
- 归档、停用、撤权与物理删除分开；未定保留期限前不默认启用破坏性 TTL。共享记忆以引用和授权计算保留，不能删除单个任务就清掉整个会话记忆。
- 本轮默认将宿主机本地磁盘挂入容器。常规备份应覆盖数据库、资产、项目、原生历史、Runner 账本和必要密钥。日常恢复遇到原生目录缺失时报告实际状态。下一节的一次性开发环境切换允许重新初始化受影响的旧 Session。

## 7. 验收与旧设计协调

此次开发环境切换从新文件布局启动，保留 PostgreSQL 中的用户、工作区、员工、业务会话、任务和平台 `sid`。旧上下文、附件、命令输出允许丢失。无需扫描、搬运或双读旧目录。

1. 停稳旧 Engine、Pi、Runner 和后台命令，释放受影响的旧执行分配，将未完成的 Turn 标记为中断。已停止或归档的业务对象保留原状态。
2. 仅对切换前受影响的旧 Session，一次性解除旧 Pi 原生身份和失效的运行绑定。按正常启动流程同步官方资源。本地存储身份包含进程所见根路径的摘要。若升级同时改变这个绝对路径，待 `sync-catalog` 校验安装包中的文件后，在停写窗口一次性更新这些内置 Skill 版本的 `storage_identity`。按本次目录清单的 Skill ID、版本 ID、原存储身份和 manifest 核对更新范围。缺失的自定义 Skill 显示为不可用。缺少旧附件只影响该附件。
3. 用户打开原会话发送新消息时，沿用平台 `sid` 初始化新的 Pi 原生会话、项目和按需使用的 Runner。切换后产生的历史和账本走正常恢复流程，后续重启不重复重置。
4. 用切换前创建的会话验证发消息、上传附件、派任务从共享项目读取、加载获准 Skill。同键重试应返回首次上传的路径。重启服务后，验证切换后产生的历史可续聊、文件可读取。

**后续 OSS 改造**将单独设计整根挂载、Runner 账本迁 PostgreSQL、Pi 历史和项目上传发布适配。届时 Engine 接管改为数据库分配与停止确认，并允许旧实例失联时接管。本轮仍以本地文件锁判断接管。

其余生命周期验收沿用以下约定。

- 两工作区、员工和业务会话的平台资源引用与模型上下文不串线；同业务会话任务复用一个项目目录。裸模式不验收操作系统安全隔离。
- task 重试、一个执行 Session 停止/归档、Engine 切换，不误停或删除其他活跃任务的环境。
- 会话最小粒度抽取，多个会话/整员工显式共享与撤销有效；共享目标身份和来源限制同时生效，不能经记忆越权。
- Hook/定时同 key 并发归一、事件幂等独立；缺失/冲突/归档/规则变更策略有明确结果，不能默默扩大共享。
- local/S3 资产适配器互读同一逻辑内容。目录重构验收覆盖本机进程重启及同一挂载盘上的容器重建，核对切换后生成的数据。配置错误应报告失败，孤儿清理保留有效引用。
- Mac/Linux 真实运行、共享项目文件冲突、按 Session 停止、进程退出及文件保留分别验收，不把目录设计当作安全隔离结果。
