# Web 群消息、员工输入与成员可见性

状态：2026-11-18 用户已确认，**实施中**；本文描述本轮目标，不代表接口、前端或端到端验收已全部完成。此规则针对 Web 群，不自动改变 IM 渠道群或跨群共享授权。

业务配置按新平台目标统一归 AI 员工级，可选择 Web 或不同渠道名单，渠道连接设置独立；不考虑旧绑定名单兼容。Web 群支持关键词触发，仍须执行各员工当前授权。

## 每群一份消息，各员工独立 Input

Web 群消息按群保存一份共享消息事实，不为每个员工复制一套用户可见群消息。多人和多员工看到的是同一群消息记录与顺序。

每位员工独立判断触发条件，并独立校验实际触发人的当前使用权限及员工/群关系；只有通过该员工的触发与授权后，才按其输入边界补充群上下文并写入该员工自己的 Input。消息的一份共享存储，不等于所有员工均收到触发输入，也不表示所有员工共享同一个 Pi 上下文或执行权限。

同一条群消息可触发多个获准员工，分别关联各自 Input；一个员工不命中、拒绝或执行失败，不替其他员工作出结论。群消息身份与员工 Input 身份分开，重试不得重复创建群消息或重复派发给同一员工。具体表、幂等键、分页与事件契约以实现核对，不在本文先行固定。

## 新加入成员可以查看加入前历史

新增人员和新增员工均可以查看加入前的群历史，不能以加入时间作为历史下限。这是本轮明确决定，撤销此前“只能看入群后消息”的假设。

人员或员工加入本身不要求重置其他员工或已有会话的 Pi 上下文；撤销“新成员加入即重置 Pi”的假设。新增员工仍有自己的输入与运行上下文，可以在其实际受理时读取获准群历史；不复制其他员工的私有运行记录或工具授权。

可读取群历史和可触发某员工是不同权限。前者不替代该员工对触发主体的当前授权，也不把历史发言当作新的执行授权。

## 退出、移除与迟到结果

人员退出或被移除后不得查看后续群消息，员工退出或被移除后也不得继续取得后续群上下文。历史查询、最近页、分页游标、实时订阅与重新连接都必须执行当前成员和工作区/群身份隔离检查，不能仅在首次打开页面时检查。

已领取输入、在途任务、回告或迟到结果不能凭旧成员快照绕过退出状态。后续执行、读取群上下文以及向群投递时须分别复验当前授权和目标状态；业务已发生事实与是否允许新的披露/发送分开记录。具体取消或抑制策略由实现与后续决策核对，不在本文擅自规定为任务级联取消。

用户已明确：退出或被移除后不能再打开该群，也不能通过旧链接、历史分页或实时订阅继续读取群内容；不保留退出前历史的独立回看入口。重新加入的具体成员记录恢复方式按实现核对，不能自动恢复旧执行权。

## 已确认的群内员工可用性与角色

用户已确认采用群成员免 allow 模式（方案 B）：每位员工的群成员免 allow 开关默认开启。在员工参与的群内，当前群成员可使用该员工，不要求另命中 allow；deny 始终优先。关闭该开关后，按员工级统一使用范围判断。该模式不免除触发条件、员工启停、当前成员身份、能力包和工具操作授权，也不授予跨群读取或私聊使用权。配置归员工级，不另建旧式渠道绑定独立名单。

用户已同意按此前推荐的群主/群管理员方案并行实施：群主和群管理员属于群自身角色，与 workspace admin 独立。群级管理不能暗中变成员工配置管理权，workspace admin 也不因该角色自动成为每个群的群主或群管理员。本页不额外规定未讨论的邀请接受、管理员互相移除、接管或解散细节，具体操作矩阵按已确认方案与实现契约核对。

## 验收要点

- 一条群消息只有一份共享事实，分别触发多个员工时只产生各自唯一 Input。
- 员工 A 命中/授权失败不影响员工 B 的独立判断，普通群消息不误触发所有员工。
- 新加入人员和员工均能读取加入前历史；加入不重置已有 Pi 上下文。
- 退出或移除后不能打开群，列表、详情、历史分页、实时流和重连均不能绕过成员校验；跨群、跨工作区、同名身份不串线。
- 退出与输入领取/任务完成/回告投递并发时仍按当前权限裁决，迟到回执不重新授予成员权限。

- 群成员免 allow 默认开启、deny 优先；关闭后按员工统一使用范围，不能把模式误当免除触发或能力授权。

测试与真实 UI 联调结果由实施报告补充。上述群内可用模式已确认；本页不扩展跨渠道共享策略或未讨论的管理细节。

## 本轮已接入的后端群管理接口

2026-11-18：Platform 已装配群列表/创建、详情/全量更新和本人退出入口；机器契约见 [Web 群合同](../../backend/contracts/modules/platform/web-groups.yaml)。前端尚未交付，本节不表示真实 UI 或外部模型端到端验收完成。

- `GET/POST /api/v1/workspaces/{workspace_id}/web-groups`：当前有效工作区成员可创建；创建人是唯一群主。列表仅返回当前可见群，按创建时间倒序、ID 排序；支持 q 名称子串查询及 page/page_size 页码分页。列表 roster 数组为空，成员明细读详情；当前空页 total 返回 0，不表示完整授权集合一定为空。
- `GET/PUT /api/v1/workspaces/{workspace_id}/web-groups/{group_id}`：当前群成员才可读取，工作区管理员无旁路；更新仅限群主/群管理员。PUT 提交 `version/title/status`、完整 `members[{user_id,role}]`、`agents[{agent_id}]`，不是增量补丁。遗漏成员即移除，须保留唯一群主；版本过期或群已归档返回冲突，不得自动换新版本覆盖。
- 群角色为 `owner/admin/member`。仅群主可转让群主或归档。添加人员须为有效工作区成员；新增员工须通过当前可用性/统一使用范围检查，保留名单不等于恢复已停用员工执行权。
- `POST /api/v1/workspaces/{workspace_id}/web-groups/{group_id}/leave`：本人退出；群主须先转让，已移除成员重复退出不重复推进。移除/重新加入通过代次阻断旧执行上下文，不自动恢复旧请求权限。
- 登录使用 Cookie，写入须同源及 `X-CSRF-Protection: 1`。创建群目前无幂等键去重，响应未知时不要自动重试创建；退出不删除群消息。

Manager 另已装配同一群下 `GET/POST /messages`：读以 `after_seq/limit` 分页，写为 `text/mention_agent_ids` 并要求 `Idempotency-Key`，客户端不得伪造发言者或系统消息类型。消息仍是每群一份、各员工分别受理；消息端点不复用旧个人 Session 公共入口绕过群成员校验。

实施验证：已有隔离数据库的群任务委派→Task→回告→群消息链测试、退出/移除代次检查及 HTTP 登录/CSRF/伪造系统字段测试；模型轮次为 fixture，不宣称真实外部模型或浏览器验收。群管理及消息实现分别归 Platform 与 Manager，schema 由统一迁移维护。
