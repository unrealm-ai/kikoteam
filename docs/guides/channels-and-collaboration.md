# 渠道接入、自动化触发与人机协同指南

本指南介绍如何将 AI 员工接入飞书、钉钉和企业微信，如何配置跨群历史共享、定时计划与 Webhook 触发器，以及如何在后台任务中使用人工确认和跨员工事项交接。

## 1. 接入办公 IM 渠道

KIKO 的 `event-hub` 组件通过各平台官方的长连接协议（飞书 WebSocket、钉钉 Stream、企业微信智能机器人长连接）主动向外建连收发消息。这意味着**在本地开发或企业内网部署时，无需为 IM 渠道暴露公网 Webhook 回调端口**即可完成机器人收发。

进入「**AI 员工 → 选择员工 → 渠道**」页签，可分别绑定三大办公渠道：

| 渠道 | 连接协议 | 接入方式 | 支持的交互能力 |
| --- | --- | --- | --- |
| **飞书** | 官方 WebSocket 长连接 | **扫码创建**智能机器人，或**手动绑定**已有飞书应用凭据（App ID / App Secret） | 私聊、群 @ 机器人、**群话题（Thread）原位回复**、富文本（`post` 标题/文本/链接/提及/代码）解析、Markdown 与表情回复、通讯录部门与成员同步、近期群历史与跨群共享 |
| **钉钉** | 官方 Stream 长连接 | **扫码创建**智能机器人，或**手动绑定**已有机器人凭据 | 私聊（含文件附件）、群 @ 机器人、富文本（`richText` 文字子项）入站、Markdown 回复、通讯录部门与人员同步 |
| **企业微信** | 智能机器人官方长连接 | 官方弹窗授权或**手动填写** Bot ID 与密钥（首次入站消息确认身份） | 私聊、群 @ 机器人、图文混排（`mixed` 文字子项）与文字引用解析、近期群历史截取、联系人关键词搜索与验证码核验绑定 |
| **Web 工作台** | 同域 HTTP + SSE | 创建员工后默认开启 | 唯一固定私聊、**Web 多人多员工群聊**、私聊项目目录树与拖拽上传文件、任务进度卡片与实时事件流 |

### 渠道接入注意事项

- **连接状态与诊断**：每个渠道卡片会分别显示「配置已保存」「凭据已认证」「连接在线」及最近一次真实收发时间。飞书扫码接入还会展示各项权限的诊断结果。
- **附件与富文本边界**：三渠道的富文本和混合消息会按原顺序保留标题、文字、链接、@提及、代码块和文字引用；当前版本对渠道入站消息中的纯图片/语音资源仅作占位跳过，不会下载送入模型。Web 私聊和钉钉私聊支持文件附件上传并交由后台任务分析。
- **换绑机器人保护**：更换已绑定的机器人凭据前，界面会列出受影响的身份映射、黑白名单和群共享规则；确认换绑后，旧机器人身份关联的名单条目会自动失效，防止跨租户越权。
- **自定义钉钉扫码来源（可选）**：自托管管理员可通过 Backend 环境变量 `KIKO_DINGTALK_REGISTRATION_SOURCE`（默认 `kikoteam`）自定义钉钉扫码登记的来源标识。

## 2. 群历史隔离与跨群共享

默认情况下，不同群聊、飞书不同话题（Thread）以及每个人与 AI 员工的私聊上下文**严格隔离**，员工不能在 A 群读取 B 群的聊天记录。

如果项目组需要让 AI 员工汇总多个关联群的讨论（例如让周报助手同时读取「研发群」和「测试群」的近期上下文），可在员工配置中开启**群共享**：

1. **项目组互通**：将同一项目的若干群加入互通组，群内获授权调用时可按规则读取同组群历史；
2. **定向信息同步**：授权某位指定成员或目标群单向读取指定来源群的近期历史。

> 能够「在界面选中某个群」「调用某位员工」「使用某个能力包」与「读取另一个群的历史」是四个相互独立的权限，均由 Backend 在每次执行前逐项核验。

## 3. 自动化触发：定时任务与 Webhook

除了被动等待用户在聊天中委派，AI 员工还可以通过「**触发器**」自动在后台发起任务，并将结果发送到指定群聊。

在「**AI 员工 → 选择员工 → 触发器**」页签中支持配置：

| 触发器类型 | 配置内容 | 幂等与安全机制 |
| --- | --- | --- |
| **Cron 定时任务 / 固定提醒** | 任务提示词（Prompt）、执行周期与时区、执行身份、结果接收群，以及在「使用范围」中为该触发器开放的能力包操作 | `event-hub` 持锁调度，滚动重启期间**同一期计划严格只触发一次**；停机期间过期的历史计划自动跳过，不扎堆补跑 |
| **GitHub / 通用 Webhook** | 外部事件来源、签名密钥或认证方式、稳定事件 ID 提取规则、绑定的员工处理 Prompt、结果接收群 | 外部系统调用 `POST /api/triggers/events/{trigger_id}`；校验签名与速率限制，**相同事件 ID 自动幂等去重** |

> [!TIP]
> 新建的触发器规则默认处于**停用**状态。请先核对执行身份、该触发器在各能力包中被授予的工具范围以及结果接收群，确认无误后再启用。任务执行完成与群消息投递回执会分开记录——即使目标群临时发送失败，你仍然可以在工作台「任务」中心查看完整执行结果并一键重试投递。

## 4. 人机协同：后台任务人工确认

当后台任务遇到需要业务拍板的问题（例如：「*本月财务报表采用口径 A 还是口径 B？*」或「*即将执行外部写入操作，请确认变更清单*」）时，AI 员工可以使用内置的人工确认机制：

1. **发起确认并停稳等待**：后台任务指定工作区内的某位成员作为**确认人**，附带问题说明、背景上下文（或代码/数据 Diff）与候选项，当前任务 Session 自动进入 `requires_action`（等待人工）状态并安全停稳。
2. **多端提醒与权限隔离**：
   - 工作台顶部导航栏与「**任务 → 人工确认**」中心会显示待处理提醒；
   - 如果配置了渠道通知，系统还会通过私聊向指定确认人发送持久化通知；
   - **只有被指定的确认人（或拥有来源任务读取权限的成员）能看到完整问题背景与提交答复**，其他工作区成员仅能看到最小状态摘要。
3. **答复后原位续跑**：确认人在 Web 工作台或私聊中直接回复（支持结构化编号选择、补充修订意见或请求进一步澄清并显式批准）。确认生效后，系统会在**原有的 Task 和 Session 上**提交一条新的 `Input`，由 `agent-engine` 加载原 Pi 会话历史继续执行下一轮（`Turn`），同一问题只生效一次答复。

## 5. 多员工接力：事项看板与跨员工交接

对于需要多个岗位协同完成的工作（例如：「研发交付助理」写完变更总结初稿后，交由「合规审核专员」复核，最后交给「内容运营编辑」发布通告），KIKO 提供了**事项（WorkItem）与跨员工交接**：

1. **自动建项与转交**：当前 AI 员工在任务中发起交接时，系统会自动创建或推进一条**事项（`WorkItem`）**，将结构化的阶段目标、当前进展、待办要求以及获准移交的固定版本文件生成**交接单（`Assignment`）**，派发给接手的 AI 员工。
2. **权限与上下文隔离**：接手的 AI 员工使用**自己独立的任务（Task）、执行会话（Session）、模型配置和能力包授权**开展工作，只能读取交接单中明确移交的材料，不会越权访问上一位员工的私有会话记录或插件凭据。
3. **三列事项看板与验收闭环**：进入左侧「**任务**」导航，默认打开**三列协作事项看板**，可直观查看每项工作的当前负责员工、交接链路和里程碑通知；下游员工完成后，成果可返回原任务完成验收闭环。
