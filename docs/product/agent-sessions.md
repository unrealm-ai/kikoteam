## 1. 目标与范围

当前链路为：配置 Agent → 创建 Session → 提交文本 Input → 执行 Turn → 使用模型与获准工具 → 返回文本及执行状态 → 继续输入或停止执行。先交付后端 API，自行定义协议，参考文件 `agent-session-protocol.html` 不构成兼容要求。

| 当前资源 | 含义 |
| --- | --- |
| AI 员工（历史字段 agent_id） | 持续身份及一套面向任务执行的配置，不另建 Agent 主体 |
| CapabilityPackage | 员工绑定的资源组合与使用范围；工作区模板复制后独立 |
| ModelProfile | 某个具体模型的完整调用配置 |
| Skill | Harness 可以读取的普通技能目录 |
| Plugin | CLI 或 MCP 能力定义，可附带 Skill |
| PluginAuth | 插件授权，保存认证配置、凭据引用和授权状态 |
| 业务会话 Conversation | 同一员工下的业务范围；按需唯一主 chat Session，多个任务及唯一当前共享 Sandbox |
| Task | 一件业务目标；Backend 同事务创建 Task 与唯一 task Session，补充和继续不新建它们 |
| 执行 Session | 属于业务会话的独立模型上下文，区分 chat/task |
| Input | 平台已经受理的一次文本输入 |
| Turn | 处理一条 Input 所产生的一轮执行 |

前端按已交付管理功能推进；渠道、业务定时、指定确认人和事项交接暂缓。Conversation / Task / Session / Sandbox 的创建、停止、归档及回收已按[生命周期设计](../architecture/conversation-lifecycle.md)确定。主 chat 的[会话委派 MCP task_delegation](../../backend/docs/task-delegation-mcp.md)已设计六个带 task_delegation_ 前缀的工具，复用 Manager 创建 Task/唯一 task Session/首条 Input、查询、追加和停止，代码尚未实现。业务 key 路由、业务完成判定、自动结果入上下文及唤醒仍另行细化；跨员工名单和原始主体核验就绪前不启用跨员工目标，不默认共享环境。

File、Artifact 及上传发布 API、自动记忆抽取尚未实现；业务会话共享 Sandbox 和记忆归属已确定。Skill 目录、Pi 原生历史和执行工作目录属于运行基础，不因此新增文件资源。首版采用[Mac/Linux 裸 Sandbox](../../sandbox-runner/docs/local-sandbox.md)：Engine 本机的稳定 project 目录、同账号 Runner 和工具进程，不提供安全隔离，不要求容器或独立环境系统。Agent/Session 不开放特殊环境配置；容器只保留扩展设计。

系统生成稳定资源标识，展示名可修改；资源记录归属、创建者和时间，平台核验当前访问权限。下面的参数为产品概念，具体字段、状态枚举及约束由技术契约确定。未列出的删除、回滚、草稿或发布操作不自动加入交付范围。

## 2. Agent 配置与会话模式

Agent 只维护一套配置。新建 Web 与各渠道主对话使用该员工所选模型，task 规则不变；聊天的 Harness、指令与工具边界沿用平台预设，无需另配一套模型。

| 参数 | 产品约定 |
| --- | --- |
| 名称、职责简介 | 介绍身份及可承担的工作，名称变更不影响引用 |
| 岗位指令 | 说明职责、工作方法、表达方式与要求 |
| 模型选择 | 引用 ModelProfile；任务模式思考强度及其他生成参数跟随 Harness；chat 固定关闭可配置思考 |
| 能力包 | 员工绑定的技能、插件与允许操作组合；工作区模板复制后独立维护 |
| 包内资源版本 | 新建或新绑定默认选择当时最新可用版本并固定；已绑定项仅提示更新，用户显式升级 |
| 插件账号 | 插件定义位于统一资源库，账号在员工绑定时授权；同员工同插件共用一份账号授权，各包分别限制工具 |
| 使用范围、启停状态 | 管理谁可以使用、可用能力及是否开放使用 |
| 配置版本 | 保存即生成新版本并生效，无草稿和单独发布流程 |

| 模式 | 配置及运行方式 |
| --- | --- |
| `chat` | 固定使用 Pi（独立于员工任务引擎），使用该 AI 员工所选模型、关闭思考、有限内置能力；不申请 Sandbox |
| `task` | 使用 AI 员工配置及所属业务会话共享 Sandbox；执行上下文独立，业务归属不能省略 |

chat 另外要求通过受控扩展实现后台压缩不阻塞正常对话，以及仅追加 assistant 消息且不触发模型回复；语义、并发与验收见[Engine 对话与任务设计](../../agent-engine/docs/chat-and-task.md)。这些是设计要求，尚未实现。

两种模式共用执行 Session 服务，表达运行方式；由业务层关联到所属业务会话及任务，不把执行 mode 作为业务会话隔离 key。创建会话不能覆盖岗位指令、模型、Skill、插件、授权或环境配置。创建后不修改所属 Agent 和模式。

backend 负责 Engine 注册与 Session 分配；每个活跃 Session 对应一个由 Engine 启动和管理的专属 Pi 进程，与 Sandbox 分开。同一会话按轮串行，不同会话可以并行。没有后台进程等活动的空闲进程可释放，持久目录保留；后续 Input 使用 `--session` 加载 加载原生上下文，故障中断旧 Turn，不自动续跑。进程释放不代表会话结束。

停用 Agent 后禁止创建新会话及向已有会话提交新输入，尚未开始的输入拒绝执行，已经开始的轮次正常收尾。普通停用不等于撤销工具授权；需要立即中止时另行停止对应 Session，权限撤销仍按当前权限生效。停用不归档 Session，历史、停止和归档入口仍按权限可用。重新启用后，未归档的旧会话可沿用原快照接收新输入，停用时已排队的输入不自动恢复执行。

## 3. 模型配置与版本生效

一条 ModelProfile 表示“通过哪个入口、什么协议和账号调用哪个具体模型”。同一入口的不同型号分别建配置，多个 Agent 可以引用同一配置。

| 参数 | 产品约定 |
| --- | --- |
| 名称、说明、归属 | 平台管理或工作区管理，分别维护和授权引用 |
| 协议类型 | 产品范围包括 Chat Completions、Responses、Anthropic Messages，实际支持由 Harness 接入验证 |
| 服务地址、模型标识 | 实际调用入口与具体型号 |
| 认证信息 | 按服务要求提供；无需认证可为空，普通读取脱敏 |
| 验证结果 | 最近检查时间、结果和失败原因 |
| 配置版本 | 保存更新时生成 |

工作区与官方默认模型仍可用于表单推荐，不作为主对话的运行兜底。新建 chat 与 task 使用 Agent 的模型引用，已有 Session 照原快照执行。不另设服务连接和模型型号两类管理资源，也不在 Agent 或会话请求中暴露生成参数。

| 更新对象 | 生效规则 |
| --- | --- |
| Agent | 保存即生成新版本，新会话采用新版 |
| ModelProfile | 保存生成新版本，所有引用它的新会话解析最新版本，无需逐个保存 Agent |
| 独立 Skill | 更新生成新版本；Agent 显式选用新版并保存 |
| Plugin | 更新生成新版本，包含配套 Skill；Agent 显式选用新版并保存 |
| 已有 Session | 固定实际采用的配置及资源版本，后续轮次沿用 |
| 凭据刷新、撤销与权限变更 | 后续操作核验当前状态，旧快照不能绕过撤权 |

配置快照固定资源内容并保存凭据引用，不固化可永久使用的密钥。平台版本固定自身定义与内容包；远程服务自身升级仍需核验兼容性。

## 4. 能力包、Skill、Plugin 与 PluginAuth

能力包保留资源组合及使用范围，员工通过能力包获得 Skill 与插件操作，不提供绕过能力包的直接绑定入口。工作区能力包作为模板复制给员工，不共享联动。多个包重叠时按每条包规则的有效授权行为核对，不能把人员和来源条件拆开合并；同员工多个包使用同插件时共用该员工的一份插件账号授权，各包工具范围可不同；包自身版本策略尚待确认。

### Skill

Skill 是包含 `SKILL.md` 的普通目录，可以附带脚本、参考资料和模板。平台保留完整内容，不要求额外的技能参数格式或执行流程语言。本批支持上传 ZIP 与指定 GitHub 仓库路径导入；导入固定实际 commit，不自动追踪分支。未实现的其他导入方式不在前端展示。

| 参数 | 产品约定 |
| --- | --- |
| 名称、描述 | 从 SKILL.md 读取，供发现和选择 |
| 目录内容 | 完整保存说明及附带文件；打包只是一种传输方式 |
| 归属、来源 | 平台预置、工作区导入或插件附带 |
| 版本 | 固定对应完整目录内容，更新生成新版本 |

独立 Skill 自己管理版本；插件附带 Skill 随插件版本固定。Harness 决定如何选择、读取和执行。Input 不设“指定 Skill”字段，调用方通过文本表达意图；使用 Pi 原生 `/skill:name` 时原样传入文本，平台不另行解析。Skill 本身不能授予所需工具权限。

### Plugin

一份 Plugin 的长期模型选择 CLI 或 MCP 一种接入类型，可以附带多个普通 Skill 目录。本批仅实现远程 MCP，CLI 和本地 stdio 暂不做，前端隐藏；下述 Runner 与 CLI 描述属于后续范围。CLI 保持命令形式，建议附带命令说明；MCP 按其工具接口接入。Runner 常驻 Sandbox，主动获取 backend 配置并管理环境及插件进程。builtin MCP 提供 HTTP 接入，stdio 插件通过 Runner Gateway 暴露独立 HTTP 端点，远程 HTTP MCP 由 Harness 直连；这些地址写入原生配置。builtin MCP 采用 TS 实现，提供 read、write、edit、grep、find、ls 及 bash_start、bash_poll、bash_write、bash_terminate、bash_list 共 11 个环境工具，复用方案见[内置工具设计](../../sandbox-runner/docs/builtin-mcp.md)。文件工具不新增平台 File / Artifact 资源；[独立模块](../../sandbox-runner/builtin-mcp/README.md) 已实现并完成基本验收，平台编排尚待联调。

| 参数 | 产品约定 |
| --- | --- |
| 名称、简介、接入类型 | 说明用途，类型为 CLI 或 MCP |
| 运行或连接定义 | CLI 的安装来源、程序入口和依赖；MCP 的连接或本地启动方式 |
| 配套 Skill、能力说明 | 随版本保存技能目录和对应工具或命令能力说明 |
| 接入参数定义 | 声明地址、环境参数等的必填项、默认值与敏感项 |
| 认证声明 | 声明支持的认证方式、授权检查及续期等能力 |
| 归属、版本 | 平台预置或工作区自建，更新生成新版本 |

插件定义保存“需要什么配置”，具体账号认证材料由 PluginAuth 管理。非敏感实际值仍称“接入设置”，不另设 PluginConnection 资源。缺少运行依赖时明确报告，不要求调用方另配 Sandbox 模板。更新插件或添加 Skill 不自动扩大 Agent 的操作范围。

### PluginAuth 插件授权

PluginAuth 保存某插件在特定账号、租户或环境下的一份认证配置、凭据引用和授权状态。它不是网络连接实例。

| 参数 | 产品约定 |
| --- | --- |
| 授权名称、所属插件和工作区 | 明确用途及归属，如“生产环境只读账号” |
| 认证方式、授权目标和账号 | 标明适用服务、租户、外部账号及认证方法 |
| 凭据引用或登录态 | 受控保存，普通查询不返回明文 |
| 授权范围、管理与使用权限 | 区分第三方授予的权限和平台允许谁管理、使用 |
| 授权操作者、状态及有效期 | 记录谁授权、是否有效、是否需要重新授权 |
| 验证与变更记录 | 最近检查结果及配置变化 |

一个插件可以有多份授权。账号在员工绑定能力包所含插件时完成授权，不在统一插件定义中写入业务账号。2026-11-16 已确认同员工多个能力包使用同一插件时共用该员工的一份账号授权，各包工具范围可不同；员工账号授权不构成绕过能力包的插件绑定。无需认证的插件可不绑定授权；其必要的普通接入设置仍应配置。授权属于某工作区不代表所有成员自动可用。

完整认证能力包括静态凭据、OAuth 和 CLI 原生登录，支持发起认证、查询状态、更新凭据、续期、重新授权和撤销；可以分阶段实现。仅交付后端时，由 backend 提供授权地址或设备码、状态查询及适用回调，第三方登录在其授权页面完成。授权回调统一进入 backend。

认证状态独立于插件版本及临时 Sandbox，每份授权使用独立认证上下文，不能依赖所有工作区共用的宿主登录目录。Token 刷新不生成新插件版本。不能续期时返回需重新授权，保留已完成的执行记录。认证有效和服务可用分别展示；凭据不写入 Skill、插件包、提示词或普通日志。

更换外部账号、租户或服务目标时新建 PluginAuth，再更新 Agent 的绑定并生成 Agent 新版本；旧会话保留原授权引用，不自动切换账号。同一账号及目标下的 Token 刷新、密钥轮换和重新授权沿用原 PluginAuth。首次登录可补全尚未知晓的账号身份，此后重新登录不能静默改为另一个账号。

## 5. Session、Input 与 Turn

### Session 参数

| 参数 | 来源与约定 |
| --- | --- |
| 标识、工作区、创建主体 | 系统生成或核验并记录 |
| 业务会话、员工、任务与模式 | 业务会话由调用方指定或业务入口解析并核验；员工随归属确定；task 同事务创建唯一 Task，chat 不关联 Task；mode 必填且不可改 |
| 标题 | 可选，可后续修改 |
| 配置快照 | 系统固定本次实际采用的配置和资源版本 |
| 生命周期 | 可使用或已归档；一轮失败不结束整个会话 |
| 执行概况、时间 | 汇总执行及排队情况，记录创建和最近活动时间 |

支持创建空 Session 后提交 Input，也支持携带首条文本输入。空 task 创建可以产生多个不同 Task/Session；chat 在同一 Conversation 下只有一个，重复创建受唯一约束。携带首条输入按同一去重标识复用原 Task（若有）、Session 和 Input。群/用户路由在业务层确定，不恢复交流范围或 parent_session_id 参数。

创建 Conversation 只登记元数据；首次聊天才创建主 chat Session，首次任务执行才创建共享 Sandbox。首版 task Session 固定到该环境的管理 Engine/宿主，chat 可独立调度。停止主对话不停止任务；任务停止或单个 Session 归档只收尾自身。Conversation 归档先关闭全部准入，再归档和收尾所有关联 Session，最后回收环境运行资源。活跃 Conversation 不做环境自动空闲回收，Pi 原生历史与工作文件保留，后续再定义数据删除策略。

### Input 参数

| 参数 | 来源与约定 |
| --- | --- |
| 标识、所属 Session | 标识由系统生成，目标会话由调用方指定并核验 |
| 文本内容 | 调用方提交，受理后不可原地修改 |
| 请求去重标识 | 重试同一次提交时沿用，与链路追踪标识分开 |
| 提交主体、队列顺序 | 平台核验主体并生成同一会话内的受理顺序 |
| 处理情况、关联 Turn | 排队、已开始、取消或未能执行等；排队时可以没有 Turn |
| 时间记录 | 受理及处理时间 |

本期只定义文本，不设图片、文件引用、指定 Skill 或业务任务反馈字段。正文中的名字、会话 ID 或指令不能建立可信身份。每条输入保留真实提交主体，不能继承别人的权限。

### Turn 参数

| 参数 | 来源与约定 |
| --- | --- |
| 标识、顺序、Session 和来源 Input | 系统创建并关联 |
| 状态、实际配置引用 | 记录运行、停止处理中及完成、取消、失败或中断等结果 |
| 输出记录 | 助手文本、中间输出和最终答复 |
| 工具执行记录 | 工具名、状态、摘要、错误及受控详情 |
| 结果和错误说明 | 记录实际完成情况，包括结果未知的操作 |
| 时间与用量 | 耗时及 Harness 能提供的用量信息 |

一条 Input 最多对应一个逻辑 Turn，首版不合并排队输入。一次 Turn 可以多次调用模型、工具并输出多条消息，单条消息或工具返回不代表整轮完成。Turn 由平台创建和推进，不设产物引用。

## 6. 输入、执行与控制

### 输入排队与撤回

同一 Session 的 Input 按受理顺序串行处理，不同 Session 可以并行。执行中追加输入立即返回受理及排队情况，当前轮结束后处理，区分“已收到”和“已开始执行”。

只允许撤回未开始执行的 Input；已开始时明确拒绝撤回，由调用方决定是否停止会话。修改内容需撤回后重新提交。输入提交响应丢失时沿原去重标识取得原 Input 的当前状态，同标识不同内容报告冲突。不同标识即使文本相同也视为两次新提交，均按会话受理顺序排队。

### 重试与并发原则

普通 CRUD 不统一要求幂等 key，由资源的唯一条件、目标状态和版本检查表达重试行为。标题或配置并发编辑使用预期版本，冲突时重新读取判断，不静默覆盖；撤回已取消输入、归档已归档会话均返回当前状态，不重复变更原因、时间或版本。

仅 Input 提交（含创建时首条输入）做必要请求去重，重复成功请求定位原资源并返回当前状态，不提供通用响应回放服务。停止 Session 不要求 key，每次都停止本次受理时已有的工作；网络重试也按当前工作重新确定范围，会覆盖两次调用之间新增的工作。

并发按成功提交的业务转换裁决：撤回先完成则不开始执行，领取先完成则撤回失败；输入先受理则纳入后到停止或归档的范围，停止先受理则后续输入不受这一次停止影响，再次停止会重新确定范围；归档先完成则后续输入被拒绝。同一执行 Session 串行，同一 Conversation 内不同任务可并行；具体技术约束见[并发裁决设计](../architecture/session-data-model.md#7-事务与并发裁决)。

### 输出、历史与事件

支持实时文本输出、持久化正式消息、工具进展、轮次结果和受控详情，统一使用事件历史与实时流。正式助手消息、Input 受理与状态、Turn 结果、工具参数及结果都是不同类型的事件，不再分别提供消息和工具调用查询接口。字段与类型以[会话事件协议 v1](../../backend/docs/session-events.md)为准：公共字段与业务字段平铺，核心 type 为 user.message、agent.message、agent.thinking、agent.tool_use、agent.tool_result。该目录是预设计，实现时按实际功能需要采用对应定义，不要求一次全部实现，也不意味着列出的类型当前已支持。工具详情在两种通道中均按当前权限脱敏；临时文本增量只实时发送，不承诺逐片重放。

历史分页与实时流共用可靠事件顺序，读完某次历史后可从对应位置继续，不能漏掉翻页与建连之间的变化。首版可靠事件作为会话正式历史保留，不按短期传输日志清理。断流不停止执行，重连可恢复正式文本与状态。

### 停止、继续与归档

| 动作 | 产品行为 |
| --- | --- |
| 停止 Session | 每次停止本次受理范围内当前轮、排队输入及本执行 Session 的后台进程，返回 Session 表示已受理，实际收尾查看其执行概况 |
| 停止之后的新输入 | 不受前一次停止影响，仍按串行约束等待当前轮收尾；再次停止时会纳入新的范围 |
| 失败或取消后继续 | 在原 Session 提交新 Input，产生新 Turn，保留原记录；不提供独立的重试 Turn 操作 |
| 归档 Session / Task | 仅停稳后拒绝目标的新输入并归档；Task 与 task Session 归档一致，不回收共享环境 |
| 归档 Conversation | 全部关联 Session 停稳后关闭全会话准入，再归档全部关联 Session；全部停稳后回收运行资源，保留历史及文件 |
| 归档后重新交流 | 新任务创建新 Task/Session；原主 chat 或父会话已归档时新建 Conversation，不自动复制上下文；不提供取消归档或删除 |

Session 级控制只作用于目标，停止主 chat 不停止任务。Conversation 归档是显式级联操作，父准入关闭后子 Session 即使尚未归档也拒绝新输入和领取。stop 按当前工作确定范围，无变化不重复发事件；归档不可逆，重复调用核对未完成收尾，不重复变更已归档记录。已完成结果和已发生的外部操作不改写为取消。

暂不引入 control_id、独立控制资源或控制结果查询接口。停止及归档的响应直接表示受理结果，后续通过 Session 的执行概况或统一会话状态事件观察：正在收尾、当前无工作、无法确认旧执行已结束分别明确表达。停止后若提交了新输入，会话可以进入新的排队或执行状态；需要区分轮次时使用已有 Turn 信息，不逐次追踪停止请求。

归档只读表示不再改变内容或接纳执行输入；已受理工作的结果与收尾事实仍可由运行时提交。归档与一轮结束、停止、进程释放是不同事实。

### 原生历史与故障后继续

Pi 自己持久化模型上下文，Engine 保存原生会话映射。平台保留稳定目录及身份映射，不另建逐轮检查点、检查点上传屏障或自动续跑旧 Turn 的机制。进程故障后旧 Turn 标记 interrupted、对应 Input processed；用户发送“继续”或其他文字就是新的 Input，Engine 按需启动 Pi，通过 `--session` 加载 加载原会话，再执行新 Turn。“继续”不是平台专属命令。

未开始的排队 Input 保留原有串行和撤回语义，其首次执行不等于恢复旧 Turn；没有待处理 Input 时不主动启动模型。开始新执行前确认旧 Pi 已退出、旧工具请求已排空。原生历史不可用时明确失败，不新建空白会话替代；加载历史不证明旧外部操作已停止。结果未知的操作先核对，不自动重发。

### 后台进程与 Session

后台命令归创建它的执行 Session，保留来源 Turn；工具请求结束后命令可以继续运行，正常 Turn 可以完成，下一 Turn 可以查询、写入或终止原进程。同一业务会话共享 Sandbox 不共享进程控制权，停止一个执行 Session 不影响其他 Session。

Session 执行概况分别表达对话/排队状态与后台进程数；idle 可以存在已确认的后台进程，未知计数不能记为零。stop 在没有活动 Turn 时也要收尾目标后台进程，归档则须先确认无后台活动；确认收尾前不启动停止边界之后的输入。首版有后台进程时保留对应运行实例及 Sandbox 引用，不能仅凭 Turn 完成或 idle 自动回收。

Sandbox MCP Token 与环境生命周期一致，换 Turn 和进程重启不轮换；同一执行 Session 的同范围 builtin/代理入口可共用固定 Token，共享环境内其他 Session/授权范围分别绑定。管理、配置领取及第三方账号认证各按原用途分开，不因固定工具 Token 扩大权限。

### 依赖不可用与局部失败

失去会话或 Agent 的使用权限时不启动新轮次；已受理但尚未开始的输入记录拒绝原因。模型等整轮必需依赖暂时故障时，在原 Turn 内有限重试，耗尽后明确失败，不新建 Input 或重跑整轮；重试次数和时限随后续运行契约确定。

单个插件授权过期、被撤销、运行依赖缺失或服务不可达时，禁止相应工具调用并向 Harness 提供明确错误，由 Harness 决定是否继续其他工作。平台不因此自动取消整轮或后续队列，也不改用其他账号。会话创建时仍核验引用的归属和引用权限，不能以允许局部失败为由接受越权配置；临时认证状态和网络可用性不等同于引用权限。

## 7. 身份、授权与可见性

详情、列表、历史、工具详情、事件订阅及关键请求去重返回的资源均核验当前权限。运行时代表调用主体执行，不能用内部服务身份扩大权限。创建会话和执行输入时校验 Agent、能力包、模型、包内 Skill / Plugin 及员工 PluginAuth 的可用范围；工具调用还受外部账号能力约束。

授权内的工具默认直接执行，不设置逐次确认。首次登录和重新授权属于 PluginAuth 接入管理。移除业务交流范围字段不取消工作区隔离或身份校验。资源 ID、旧配置快照或旧运行时凭据都不能绕过当前撤权。

## 8. 分阶段交付与验收

| 阶段 | 交付能力 | 验收样例 |
| --- | --- | --- |
| 基础配置与会话 | Agent、ModelProfile、独立 Session、文本 Input、Turn、流式历史、撤回、停止和归档 | 两条输入串行；撤回仅作用于未开始输入；断流后继续执行；新旧会话采用正确配置版本 |
| 技能与工具 | 员工能力包、Skill 目录、远程 MCP 插件、员工 PluginAuth 静态凭据与工具记录；CLI / stdio 后续 | 同一 Agent 通过获准包使用固定版本资源；多包同插件共用账号但各自限定工具；越权授权引用被拒绝 |
| 认证与继续完善 | OAuth、CLI 登录及续期、原生加载和控制并发行为 | 撤权影响后续调用；响应丢失可查原回执；失联后不重复产生已知或未知外部副作用 |

下列是待实现的验收要求，不表示已经通过运行测试：

- Agent 只有模型选择，无思考强度等参数；chat 的运行策略由平台固定，创建时模型取员工配置；task 使用既有员工任务配置，二者无父子依赖。
- Agent 保存即生效；ModelProfile 更新影响所有引用它的新会话；包内 Skill / Plugin 新建或新绑定默认最新并固定，已绑定项仅提示并显式升级；旧会话保持快照。
- 任务模式可独立创建，参数不含父会话、交流范围、文件引用、指定 Skill 或 Sandbox 覆盖。
- 同一 Input 最多一个逻辑 Turn，撤回与开始竞争只有一个结果；同标识重复提交 Input 不产生第二次执行。
- 普通 CRUD 不要求通用幂等 key；并发编辑检测版本冲突，重复撤回或归档不重复变更状态，空会话创建不承诺相同 ID。
- stop 不要求 key；每次只覆盖本次受理时的已接纳工作，再次调用会覆盖其间新增的工作；没有变化时不重复发状态事件。归档关闭新输入且不可恢复、不可删除。
- 会话接口收敛为 14 个操作，正式消息和工具记录统一通过事件历史及流读取；停止和归档不生成独立控制标识，实际结果直接看 Session。
- 历史分页结束后的续读不遗漏翻页与建连之间的事件，临时增量不冒充可重放历史。
- 失败或进程中断后以新 Input 经 Pi 原生历史继续，旧 Turn 不自动续跑；历史保留，外部结果未知不盲目重试。
- 两轮使用同一 Sandbox 生命周期内的固定 MCP Token；管理接口及共享环境内其他授权范围不可用该 Token 访问。
- 第一轮后台命令可供第二轮管理；无活动 Turn 时 stop 仍收尾，其他执行 Session 的进程不受影响。
- 工具当前权限和 PluginAuth 状态有效，不能凭旧快照或服务身份扩大授权。
- Agent 停用阻止新工作并拒绝未开始输入，当前轮可收尾；快速停用再启用不让旧排队输入复活。
- 单个插件失败交由 Harness 处理，模型必需依赖的有限重试不产生新的逻辑 Turn。
- PluginAuth 换账号或目标使用新记录，旧会话不切换账号，同账号密钥轮换可继续使用原授权。
- Skill 目录与默认工作目录可使用，不要求 File、Artifact 或共享目录资源即可完成文本及工具链路。
