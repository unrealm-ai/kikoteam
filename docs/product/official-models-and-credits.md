# 官方模型与积分产品设计

首版于 2026-11-18 实现。模型代理和积分复用现有平台管理员、用户管理和 AI 员工市场入口。后端 API、数据库、模块目录和验收要求由[模型代理技术设计](../../backend/docs/model-proxy.md)维护。

## 1. 目标与范围

新用户注册后获得默认 1000 积分，无须自行申请供应商 API Key，就能创建 AI 员工并使用官方模型。平台管理员统一配置官方模型、积分单价和注册赠送额度。

每个 AI 员工使用一份后台自动管理的代理 Key。代理根据 Key 确定员工及固定扣费账户，按模型实际 Token 用量结算。用户选择模型即可，不查看、复制、开通或管理 Key。

官方模型加入原有模型选择流程；工作空间自备模型继续沿用已有接入与直连方式。代理只管理模型调用及积分，不进入员工的任务、会话、工具、委派或回报内部流程。

## 2. 核心规则

| 项目 | 已确认规则 |
| --- | --- |
| 积分属于谁 | 用户账户；多个员工可以共用同一账户余额 |
| 新人赠送 | 新注册账户默认赠送 1000 积分，平台管理员可修改为非负数；设为 0 表示不赠送可用额度 |
| 赠送次数 | 每个新注册账户一次；登录、创建工作区、创建员工均不重复赠送 |
| 修改赠送额度 | 仅影响后续注册，不追溯修改已发放积分 |
| 员工扣费账户 | 新员工绑定创建人的账户；既有绑定不会因修改员工、切换模型或触发人变化而转移 |
| 按员工计费 | 调用归属和费用统计按员工记录，实际费用按所用模型的 Token 用量计算 |
| 请求准入 | 请求开始时余额大于 0，才允许使用官方模型 |
| 扣费时机 | 请求结束并取得可信用量后结算，不冻结、不预扣、不按任务暂占 |
| 允许透支 | 已放行的请求正常结算，余额可以为负；余额小于等于 0 后拒绝新请求 |
| 补充积分 | 首版由平台管理员赠送，直接计入钱包；负余额先被抵消 |
| 自备模型 | 实际走自备模型直连的调用不扣平台积分；聊天和任务分别按实际使用的模型判断 |
| 恢复使用 | 补充积分后可重新发起请求，不自动重试或恢复此前任务 |

例如：余额为 2 积分时放行一个实际费用为 5 积分的请求，结算后余额为 -3；再赠送 100 积分，余额变成 97。并发放行的多个请求都正常结算，透支金额取决于这些调用，不承诺固定上限。

员工的使用权限和扣费身份分别判断。其他成员、外部渠道或定时触发获得员工使用权限后，官方模型费用仍由该员工绑定的账户支付，不识别每条消息发送人的钱包，也不自动替其创建账户。

## 3. 模型选择与默认模型

### 统一模型下拉框

原有员工模型下拉框增加「官方模型」「自备模型」两个分组，不增加独立来源切换页或官方模型开通向导。从空白创建和从模板创建员工使用同一选择规则。

~~~text
执行模型  [通用模型 ▼]

官方模型
  通用模型       输入 10 / 输出 40 积分每百万 Token
  推理模型       输入 20 / 输出 80 积分每百万 Token

自备模型
  公司的模型服务

官方模型费用由：张三的积分账户支付
主对话和新建任务使用上方选择的模型。

                                      [保存]
~~~

示例价格只用于界面说明，不是供应商报价。选择列表显示名称、可用性和积分价格，不暴露官方服务地址、供应商凭据或员工代理 Key。

### 聊天与任务

Web、飞书、钉钉和企微新建主对话统一使用该 AI 员工明确保存的模型，自备或官方均可。不以工作区或官方默认作为运行兜底；默认模型仍可作为创建表单预选。

| 场景 | 选择规则 |
| --- | --- |
| 新员工表单初始推荐 | 优先有效的工作区默认模型；没有可用工作区默认项时使用可用的官方默认模型作为预选 |
| 新建主对话 | 创建时解析并固定员工当时所选的可用模型 |
| 已有主对话 | 继续使用原模型快照；员工更改模型不自动切换已有对话，也不改写历史 |
| 员工任务 | 保持原模型快照规则，新建用员工选择，已有任务继续使用原快照 |
| 所选模型缺失、停用或不可用 | 显示实际错误，不自动换用其他模型 |

调用官方模型时按该员工既有绑定账户计费，不因 Web、外部渠道、消息发送人或改用另一官方模型改变付费人；实际调用自备模型不会扣平台积分。这不新增上下文压缩或总结调用。

### 自动绑定与存量员工

新员工在创建时自动生成代理 Key，绑定创建人的账户。即使最初选择自备模型，生成 Key 本身也不产生扣费；以后明确选用官方模型时按同一绑定账户计费。

存量员工没有可靠的扣费绑定，不能从历史消息、使用范围或管理员身份推测。首次启用官方模型时，由具有员工管理权限的用户在原有员工设置保存，绑定当前操作人的账户，按钮附近明确提示：

> 保存后，该员工使用官方模型产生的费用将从你的积分账户扣除。

在原员工模型表单确认后保存所选官方模型即可完成首次绑定。纯改名、浏览列表或后台运行不产生首次绑定；新增官方默认项不使未确认的存量员工开始扣费。

已有绑定不因其他管理员保存员工而改变。第一版不支持扣费账户转移，不提供任意选择其他用户钱包的控件。

## 4. 平台管理页面

### 官方模型管理

平台管理员可在「设置 → 平台管理」里打开「官方模型」。工作区 owner/admin 不因此获得平台管理权，复用[现有平台管理员机制](../../backend/docs/platform-auth.md#平台管理员)。

列表字段：名称、协议、输入单价、输出单价、默认标记、启用状态、编辑操作。每一条官方模型是完整调用配置，不拆分供应商、渠道、模型池等资源。

编辑抽屉：

~~~text
模型名称        [通用模型]
接口协议        [Chat Completions ▼]
服务地址        [https://provider.example/v1]
上游模型 ID     [provider-model]
供应商 API Key  [已配置；留空输入框表示保留]

输入价格        [10] 积分 / 百万 Token
输出价格        [40] 积分 / 百万 Token
缓存读取价格    [沿用输入价格] 可选
缓存写入价格    [沿用输入价格] 可选

启用            [是]
设为默认        [否]

[测试连接]                              [保存]
~~~

密钥输入框以是否填写区分「保留」「替换」，另用明确选项表达无需认证；不把脱敏假密钥当作可提交值。

- 新连接配置通过测试后才允许启用；地址、协议、型号或凭据变更需要重测，单独改价格不需要。
- 测试分别展示连接与流式计费用量结果；连接成功不等于工具执行等全部能力已经验证。
- 修改价格只影响后续模型请求，已经开始的请求按开始时的价格结算，包括长期会话内先后发起的不同请求。
- 停用默认模型时清除默认标记；切换默认在同一次保存中完成。
- 开始被引用的模型不原地更换协议和真实型号；更换真实模型新建配置。
- 首版只有停用，没有物理删除；历史账单和员工引用保留。
- 连接测试产生的平台供应商费用不扣任何员工积分。

### 复用平台用户管理

不新建独立积分管理页面。在现有用户管理页增加：

1. 余额列。
2. 「赠送积分」操作，弹窗填写正数积分和原因。
3. 「查看账单」抽屉，查询该用户流水和模型用量。
4. 设置区的「新用户注册赠送积分」，默认 1000。

赠送按钮提交中不可重复点击，响应未知时沿同一次操作标识查询或重试，不能生成新标识自动再送一次。已有负余额正常显示，不裁剪成零。

待核对调用放在账单抽屉内筛选处理，不建立异常处理中心。管理员可补录有依据的实际用量，或确认不收费，均填写原因；已入账记录不能通过编辑页面修改金额。

## 5. 我的积分

新增用户侧「我的积分」页面：

~~~text
当前余额                   本月消耗
863.250000 积分             136.750000 积分

员工 [全部 ▼]   模型 [全部 ▼]   时间 [本月 ▼]

[积分流水]  [模型调用]

时间          AI 员工     模型       消耗积分      状态
11-18 10:30   客服助手     通用模型   0.013000      已结算
11-18 10:20   内容助手     推理模型   —             待核对
~~~

- 积分流水仅显示已入账的赠送和消耗，可展开关联模型调用的 Token 明细。
- 模型调用显示员工、模型、Token 用量、结算状态和调用 ID；未知用量显示「待核对」，不能显示为零费用或免费。
- 按员工、模型、时间查询，不提供任务或会话维度账单。
- 页面最多展示六位积分小数，保留小额调用，不把所有小额费用显示为零；大额展示可补千分位。
- 余额小于等于 0 时显示「积分不足，新的官方模型请求暂不可用」，保留账单和员工设置入口；可提示联系平台管理员赠送积分。
- 补充积分后刷新余额；不自动重新运行模型、任务或聊天输入。

账单仅允许账户本人及平台管理员查看。员工详情可向有权管理员工的人展示扣费账户名称，不因此暴露该账户余额、邮箱或其他员工的账单。

## 6. 生命周期与异常体验

| 场景 | 产品行为 |
| --- | --- |
| 停用员工 | 拒绝新的代理模型请求；已经放行的单次请求继续完成和结算 |
| 员工重新启用 | 后续调用重新检查模型、账户和余额，不恢复旧队列 |
| 扣费人退出或被停用工作区成员身份 | 拒绝其绑定员工 Key 的新请求；第一版不自动转移扣费账户 |
| 切换自备模型 | 对应调用使用原有自备凭据，不扣积分；同一员工的 Key 保留 |
| 内部 Key 轮换 | 没有用户操作入口；旧 Key 拒绝新请求，新 Key 经现有配置刷新或重启下发，不承诺运行中无缝热替换 |
| 模型调用失败但已取得可信用量 | 按实际用量收费，不能只根据 HTTP 状态决定免费 |
| 断流或超时且用量未知 | 显示待核对，不自动猜测或重发调用 |
| 补充积分 | 抵消负余额后继续可用，由用户重新发起操作 |

代理按单次 HTTP 请求裁决停用边界，不识别任务或 Turn。现有底座「当前轮可以收尾」仍是运行控制语义；若停用后该轮还需发起新的官方模型请求，会被代理拒绝。员工停用提示应说明此差异，不能承诺整个任务仍一定完成。已经直连的自备模型沿现有行为处理。

## 7. 明确不做的内容

- 不开放员工 Key 的查询、开通、启停或轮换 API，不建立 Key 管理页面。
- 不建立员工钱包、积分分配、任务冻结、预扣或透支授信。
- 不做支付、充值订单、套餐、积分到期和自动补充。
- 不做模型供应商池、自动故障切换、跨协议转换或单独部署的代理服务。
- 不建立低余额通知阈值、主动提醒、独立统计汇总表或通用配置平台。
- 不按任务、会话、渠道消息发送人分摊费用，不向员工内部流程传播计费字段。

## 8. 迁移与产品验收

既有账号初始化零余额，不追溯发放新人积分；需要时由管理员赠送。员工、自备模型、默认项、已有会话快照与历史都不因本次调整而改写。存量员工首次启用官方模型时才明确建立扣费绑定。

首版验收覆盖：新人注册、空白创建、模板创建、官方模型调用、按员工查询、管理员赠送及设置、并发透支、存量员工首次绑定、已有绑定不转移、未知用量展示、各角色可见范围，以及自备模型回归。已执行的检查和环境范围见[实施验证](../../backend/docs/model-proxy.md#12-实施验证)。
