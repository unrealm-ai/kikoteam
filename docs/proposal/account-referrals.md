# 账号拉新邀请

拉新链接仅归因，不授予工作区权限。现有工作区邀请表、角色、有效期与接受流程不变。活动默认关闭，平台管理员可在「设置 → 平台管理 → 用户管理」调整。

## 入口

真实平台登录后在工作台顶部展示「邀请得积分」，点击生成或读取本人唯一的长期推荐链接 `/r/<code>`，强调每成功邀请一位新用户可得 100 积分。链接打开原注册界面，也可切换到登录。登录已有账号不会归因、入组或领奖；新账号照常创建个人工作区和领取注册赠送。生产平台注册入口目前只有密码和邮箱验证码；Mock Google OAuth 和插件授权回调不是平台注册入口，不接入归因。未来新增平台登录提供方时，仅已验证邮箱的新账号走同一归因、发奖规则。

## 数据与一致性

独立的推荐码表与新账号归因表分别维护链接及归因。一账号至多一个码；不设到期时间，预留撤销状态。服务端仅在创建账号时认领有效推荐码，新账号唯一，不能事后改绑。密码注册记录归因但不发奖，完成现有邮箱验证（当前为邮箱验证码重置密码）才结算；验证码注册可立即结算。既有账号验证邮箱也不会新增归因。

开关持久化在平台积分设置，单独维护活动代次。关闭后旧链接可正常注册／登录，不记录新归因，不发奖励；再次开启时链接可继续推广，但关闭期间的注册及旧代次尚未发放的奖励不补发。已到账积分不撤销。无效或撤销的码不阻断注册。推荐表和钱包均为平台数据。

发奖与新账号入库或邮箱验证同一事务，锁定开关版本及链接状态后，以新账号 ID 去重，向邀请人的现有钱包写独立 `referral_bonus` 流水。有效推荐码不持有任何登录或业务权限。`GET /api/v1/referrals/me` 只查询当前活动及本人的码；`POST /api/v1/referrals/me` 显式生成／复用；平台管理读写独立端点并检查管理员角色、版本和 CSRF。浏览器仅将推荐码发给注册接口，不发给登录接口，不把浏览器时间用作归因凭据。

## 验收

覆盖验证码注册、未验证密码注册、后续验证、重复回调、同时生成同一账号的码、关闭和重启活动、无效／撤销码、旧账号登录、工作区权限隔离及平台管理员授权。新增迁移和 API 契约按仓库流程验证。
