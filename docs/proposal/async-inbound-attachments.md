# 入站附件异步准备与按需读取

状态：已确认，待实现和验证。本提案不代表当前版本已经支持。

## 范围和可观察行为

- 四个入口：Web 私聊、飞书、钉钉、企微。保持各入口现有的身份、授权和触发条件；不借附件扩大支持的群类型、文件格式、历史读取或群共享范围。Web 群不新增附件能力。本次只改入站，不改产物发布、选中后发送、渠道出站格式和回执。
- 用户有权发送且正文或有效附件引用满足既有校验时，Manager 先持久接收消息、有序附件元数据和准备工作，再按原规则提交 Input。不等待附件字节就绪。同一会话下一条文字不因之前附件下载、重试或失败被堵住；消息的提交顺序、归属及触发规则保持不变。只有附件的合法消息也能进入 Input；无法解析任何有效附件的空消息仍不应伪装为成功。
- 附件准备状态与消息受理、Agent 轮次、任务状态分开。附带稳定的附件 ID、名称、类型/媒体类型、顺序及已知大小等必要元数据；供应商未提供的数据不编造。附件到达、失败或重试只更新附件状态，不自动再创建 Input、启动新轮或重放已经受理的用户请求。一个附件失败不吞其他附件或正文。
- Web 已有会话项目文件沿用现有有序路径。待上传附件通过会话归属的服务端附件引用和消息关联，浏览器单独传输并展示每份附件的上传进度、就绪或失败及可用的单项重试。进度和下载按钮必须来自真实文件/上传状态；不把消息受理误报成文件可用，不把渠道下载展示为虚假的精确字节进度。

## 实现边界

1. **接收与状态。** 继续用已认证的渠道回调和 Manager 的入站检查。来源消息/附件序号稳定去重；同一个事件或请求重试不复制附件、不重复触发。准备工作与消息接受保持可恢复的一致性，避免只有内存的排队记录；开始主对话轮次不取决于任何尚未结算的附件。仅在有授权且确实可收取时登记或领取；领取及保存就绪结果前重新核对同一工作区、员工、会话、原始消息和当前绑定身份。
2. **后台准备。** 上传/下载与会话 Input 消费解耦。飞书按原消息 ID 与资源键、钉钉用原应用的下载码、企微按原回调的 URL 与解密信息，由 Event Hub/既有渠道能力准备；Web 走既有受限项目文件上传能力。沿用有界大小、超时、重试、并发和可恢复租约；验证返回、限制重定向和目标，仍按原会话原子发布文件。重复或过期 worker 不得覆盖较新的结果。临时失败和最终不可用分开，不能无限等待或无限重试。 钉钉官方换链 API 返回的绝对 HTTP/HTTPS 地址按原协议、主机、路径和签名下载，不做协议改写或固定域名放行。两种协议只接受各自默认端口，每跳仍校验实际连接 IP；已进入 HTTPS 的链路不降级。明文下载只适用于这一钉钉链路，下载不携带应用凭证，日志不记录签名地址。测试覆盖跨地域地址、原签名保持、两种标准端口的公网防护、拒绝内网与降级，以及企微与飞书规则不变。
3. **Agent 查询。** 主对话只接收上传事实、可选文件名及委派引用，不接收准备状态。用 `[附件 名称="文件名" attachment_id=引用ID]` 表示，每个附件一行，缺名时省略名称。普通输入和运行中追加输入均遵守此规则；缺名附件仍可委派，文件就绪状态由执行任务查实时工具。 通过 Manager 的受控 MCP 接口由 Agent 查询本次获准的附件引用。接口不请求渠道、不下载、不等后台任务：准备中立即返回 `pending`；已下载且可访问时返回用于原会话的相对路径及必要元数据；已失败/不再可取得时返回真实不可用状态；跨域或撤权拒绝，不暴露附件存在或路径。模型不得提交任意 URL 或本机路径来换取下载。附件也不会自动转成主对话模型的视觉块。
4. **授权与秘密。** 助手语境中的附件 ID、文字或路径不是授权。工具根据可信会话、执行身份和当前有效来源检查访问；任务只能获得明确随同委派授权的引用，其他会话、群话题、工作区、绑定及未经授权的独立任务不得借用。沿用现有公开文件读取权限。用于下载的 URL、下载码、解密材料及应用凭据不进入 Prompt、模型端事件、前端/API 响应或日志；需要持久化的定位信息沿用有作用域的加密存储并在终态清理。

## 本轮确认的补强

- 三个 IM 渠道的入站附件放宽到每件 100 MiB，下载和 Manager 保存采用相同上限。验收覆盖恰好上限及多一字节、企微按明文判断、内部写入接口正确拒绝超限。Web 和出站、事项及工具上限不在本项范围。

- 钉钉、企微的临时下载继续限制端口和跳数；企微要求 HTTPS 并保留原域名名单，钉钉按上述官方换链结果的原始协议下载。每次新连接还要核对 DNS 结果并只拨已核对的公网 IP，防止重定向或 DNS 回答把附件下载打到内网、回环、链路本地或云元数据地址。临时附件下载不使用环境 HTTP 代理（否则不能校验真实连接目标）；飞书固定 API 路径及其他请求不变。保存与下载共用的重试次数不变。
- 通过内置 MCP 的普通 `read` 读到 PDF 文件头时，返回请使用受管 Bash 的 `pdftotext` 提示，不返回二进制内容。文件扩展名不是判断依据，普通文本和图片保持原行为。Engine 只在 PostgreSQL 事件和摘要持久化边界将实际 NUL 改为替代字符，字面量 `\u0000` 不变，工具结果和 Pi 原生历史不变。
- 签名链接和 DNS 夹具验证仅连接合格的目标、每次跳转独立检查、代理不能绕开、重试预算不变。合成 PDF 用真实 MCP 入口验证提示和普通文本/图片兼容；合成带 NUL 的事件走隔离 PostgreSQL，覆盖事件、摘要及后续正常完成。自动化通过后在本地重启，用真实附件复测。

| 编号 | 前置条件、动作与可观察结果 | 验证方式 |
| --- | --- | --- |
| ATT-01 | 四入口分别提交现有授权范围内的纯附件、文字加附件；故意卡住下载/上传，首个 Input 仍带有序引用，紧随的同一会话文字可处理，其他会话也不受影响。 | 四入口各自夹具；隔离 PostgreSQL + 并发；实际 Engine/Pi 验证给模型的是引用而非秘密 |
| ATT-02 | 人为保持附件准备中，调用 Manager MCP 立即返回 pending；完成后查询返回已授权的相对路径并可按原工具读取；终止失败时如实返回失败。就绪状态不启动第二轮、不重复发出收到回复。 | 真实 MCP 入口、隔离 PostgreSQL、受控慢下载，不把工具调用成功当文件内容已经读取 |
