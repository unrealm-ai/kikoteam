# 渠道原消息接收反应

状态：已实施。当前行为和验证见[正式规范](../spec/channel-receipt-reactions.md)。

- 飞书、钉钉的真实用户消息，通过现有去重、触发、权限与附件检查，并提交为能触发员工的当前 Input 后，最多尝试一次在该原消息追加“已收到”语义的原生 reaction。不是长连接 ACK，也不是执行进展或最终完成。群历史、无权限、不触发、失败、控制专用消息不产生反应；企微不变。不发一条新消息，不撤回。
- Manager 在当前 Input 的同一事务标记独立、短时有效的待发送资格；不回填历史。Event Hub 在独立 worker 一次性领取（数据库提交后才能尝试），绑定和使用权限在发送前复查。不依赖模型，也不进入常规回复 outbox。领取丢响应、进程退出、提供方超时或配置不可用时可能省略反应，不重试，不影响原消息、Input 或最终回复。
- 飞书：应用机器人给原 message_id 添加 OK；新扫码授权请求加可选 im:message.reactions:write_only，已有与手动应用读取现有诊断证据，不自动扩权。无已知权限或外部接口不允许则安静跳过。
- 钉钉：机器人开放接口 emotion/reply，使用回调业务 msgId 及 conversationId，不用 Stream envelope 的 messageId，不使用用户 CLI。按钉钉 Channel SDK 的 text emotion 结构固定展示“已收到”。缺权限或接口错误安静跳过。真实客户端展示留作后续获授权联调，不用假发送代替验收。

验收：输入提交前（包括附件未准备及历史仍在读取）不可领取；仅首次成功 Input 可以领取且并发不可重复；失败、控制、企微、旧记录不产生；在途撤权、换绑、未知飞书权限不调用外部接口；合成提供方端验证请求路径、原始消息 ID、body、鉴权身份和无失败重试。隔离数据库验证资格与 Input 的原子性及迁移，不接入真实渠道。
