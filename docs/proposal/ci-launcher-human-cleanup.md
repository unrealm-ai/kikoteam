# macOS 启动器兼容与人工确认静态检查修复

状态：已实施。验证结果见下；Engine 复杂度告警不在本次改动范围。

- macOS 系统 Shell 在 UTF-8 环境下可能误读紧接全角标点的裸变量。只给冲突软件包名和构建版本变量加花括号，保留错误码、安装保护和服务启动顺序。
- 三处人工确认查询加延迟关闭作为兜底，保留所有原有显式关闭和错误处理。短码判断改写为等价条件，仍只允许第 1 版匹配旧 ID。

验收：启动器测试通过，包含 UTF-8 冲突提示且不调用安装，以及脏工作区如实显示版本并正常启动；完整 Compose 启停使用隔离实例。后端运行项目静态检查和隔离 PostgreSQL 回归，验证人工确认引用、澄清、短码以及旧 ID 兼容。不能运行的检查与实际通过的检查分开记录。

正式行为基线：[本地 Compose 启动器](../spec/local-launcher.md)；[人工确认私聊回复](../../backend/docs/human-dm-replies.md)。

- 本机严格 UTF-8 启动器黑盒回归 25 项通过；隔离 Compose 从干净配置启动，入口和 Engine 健康，停止再启动后配置及内部令牌不变。Docker 冲突分支使用替身，不卸载真实软件包。
- Backend 与共享触发模块 lint 无告警，三份 Backend OpenAPI 校验通过；人工确认编号兼容单元测试通过。
- 全仓 lint 仍会报既有 `agent-engine/internal/pi/config.go` 的复杂度超限，本次按确认范围保留。
- 隔离 PostgreSQL 人工确认专项（含三渠道路由、撤权、改派和迟到回执）与真实 Engine/Pi 人工确认端到端通过，端到端使用测试模型服务；Backend 构建通过。全量 Backend 回归在本机达到 300 秒的包级超时，未完成，未据此变更 CI 或超时设置。
