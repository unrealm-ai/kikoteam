# 钉钉主动发送缺权限提示

状态：已实施并通过自动化回归，未用真实租户做撤权测试。现行行为见 [DING-REPLY-04](../spec/dingtalk-session-reply.md)。不做权限预检，不自动发测试消息。

## 技术方案

- 「企业内机器人发送消息权限」同时覆盖主动私聊和主动群聊，不分开显示。只有真实主动消息投递收到钉钉明确缺少应用发送权限的回执，才在对应 AI 员工的钉钉绑定上记录提示。机器人未入群、收件人问题、限流、媒体上传失败或网络异常不提示缺权限。
- 任务回告、主动通知、主动发送文件、以及普通回复回退后实际尝试主动发送，均可产生此权限提示。普通 SessionWebhook 回复不计入。后续任一种主动发送确认成功后清除；仅受理、查询未确认或结果未知不能清除。保存绑定代次和原发送尝试顺序，防止旧绑定或迟到回执覆盖新事实。
- 渠道页在连接状态旁显示小提示，可悬停或键盘聚焦查看需申请的「企业内机器人发送消息权限」。通讯录沿用自动同步结果，授权不足时说明「通讯录部门成员读权限」「成员信息读权限」及对应人员/部门授权范围。保留钉钉开发者后台入口，不自动申请权限。
- 不传递供应商原始响应、用户身份、消息内容或凭据。不改变发送、重试、鉴权或回执是否能确认的规则。

## 验收

| 场景 | 预期 |
| --- | --- |
| 主动私聊或群聊明确返回缺应用权限 | 当前绑定只显示一个提示，悬停或聚焦指出所需权限 |
| 机器人不在群、收件人无效、限流、网络异常、上传失败 | 不新增权限提示，也不清除已有提示 |
| 此后任一种主动发送被确认送达 | 清除提示；普通 webhook 回复、仅受理及查询结果未知不清除 |
| 较早的失败/成功回执迟到、旧绑定回执或重复回执 | 不覆盖更新的结果，不污染当前绑定，不重复发消息 |
| 通讯录缺权限或授权范围 | Tooltip 给出权限名、授权范围；保留管理员跳转入口 |
