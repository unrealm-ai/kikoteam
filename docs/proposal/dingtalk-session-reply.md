# 钉钉普通回复使用原会话入口

状态：已实施，本地专项验证通过。

仅普通文字或 Markdown 回复（私聊、群聊）优先走入站 Stream 回调提供的 `sessionWebhook`。定时及 Hook、人工确认、任务回告、附件维持现有主动发送。入站身份及 Backend 持久受理仍是前置条件；Event Hub 仅在内存按绑定、代次、配置及规则版本、租户、群或用户、原消息记短期回复凭据，尊重供应商过期时间，限制缓存与清理，不写日志或持久化。只接受钉钉官方 HTTPS 主机与回复路径，不跟随重定向。不从正文或最近另一消息提取。

缺失、过期、Hub 重启或不能核对原目标，且尚未发送时沿用原有主动路径并执行原有授权。若已尝试 webhook，失败或结果不明不自动再走另一条路；成功只记钉钉明确的业务回执，用原消息标识绑定证据，不伪造供应商出站 ID，不发起主动接口状态查询。保留现有主动发送的回执及查询契约。

验收：模拟官方回调与响应，覆盖文字/Markdown、私聊与群聊、选路隔离、缺失/过期、换绑、错误目标和重放、URL 校验、重定向、业务失败及结果未知不重发；验证 Backend 只给符合条件的普通回复返回授权标志，旧锚点和主动目标不变，并仅接受绑定原消息的受限回执。运行渠道及后端专项和两组件 lint，不发送真实消息。

结果：Event Hub 渠道包 race 测试、Backend 隔离 PostgreSQL 投递回执与查询专项、两组件 lint 和 OpenAPI 校验均通过。见[正式行为基线](../spec/dingtalk-session-reply.md)。未做真实钉钉账号收发。
