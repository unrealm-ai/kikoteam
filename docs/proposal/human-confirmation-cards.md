# 人工确认卡片

状态：已评审方案。以本分支测试结果更新正式规范；尚未验证的行为不计为已实现。
测试代码保留在 test/channel-card-diagnostics；正式功能从 main 独立开发。

## 业务契约

- 同意／拒绝：decisionRequired=true，questions 可为空。用目标、背景、拟执行动作和影响范围描述，决定是 approve/reject，不是题目选项。
- 提交：decisionRequired=false。单选、多选、文字和数字题可以各自单独出现，也可以混搭，每题独立标记必答。choice 和 multi_choice 传选项 ID、显示文案；文字、数字直接传实际值。老式顶层文字答案仍走 text，结构化文字题继续用对应 questionId 和 value，原有逐项回复机制保持。通知要明确要求回复什么，不把已发送当作已答复。
- ask_human 不指定渠道或渲染。list_pending_human_confirmations 返回当前用户有权回答的确认单、版本、题目、选项 ID 和文案。文字答复从列表匹配，歧义时澄清；保留飞书可信引用的渠道消息 ID。
- 卡片与文字归一到同一事务，单选用 value，多选用 optionIds，拒绝或同意用独立 decision。同一确认单版本只能接受首次有效答复，不重复续跑。卡片回调单独核验真实点击人、原投递和版本，不把它冒充一条用户聊天消息。

- 同意或拒绝可附选填说明，复用提交答复的 text，不改变发起或待确认查询。模型只传用户明确表达的说明。批准时随冻结答案进入原任务续跑上下文；拒绝仍停止，不额外启动执行，原因留在结果与发起人回告。无法内嵌文字的模板允许先用「拒绝＋说明」文字提交，不要求先点按钮。

## 渠道与失败策略

- 飞书用原生卡。扫码新建应用的 addons 加入 card.action.trigger，保留原有权限和事件。老应用明确未开回调时用文字。实扫码新建和已经手动配置的现有应用分开验收。
- 钉钉初版用官方示例 dac1dbec-55af-40c3-be91-6d6882ef3b66.schema 和 OpenClaw 表单 c2a6355b-9724-4f7e-9653-d33fcb3311bb.schema。固定模板 ID 由适配器管理，用户不用设置。模板不可用或题型超出能力则整单退回文字；发送结果不明时不贸然重复发送。跨租户使用与稳定性单独验证。
- 企微支持原生同意／拒绝和可表达的纯选择表单。存在文字或数字填空时，整单用文字；不拉群卡片历史解释答案。
- Web 用同一份题目和提交规则。飞书和 Web 已确认投递或发布后只向真正收件会话写去重摘要 Input，不触发 loop。飞书保留原消息标识并复用成功回执路径；Web 应依可信发布记录。
- 仅在确认事务成功后收口卡片，显示结果和原请求摘要，支持的情况下显示操作者并移除按钮。文字先答时服务端立即关闭旧卡操作；能主动刷新的渠道刷新，否则再次点击提示已处理，不改原判定。展示更新失败与提交失败分开。没有按人或题型的发送冷却。

## 验收

1. 旧文字、编号文字、结构化文字，均能正常回答；纯审批零题仍可查询并决定。验证错误选项、重复选项、非数字、必答缺失。
2. 卡片和文字分别回答同一题，以及同时回答；错人、过期、改版和回执重放都不能重复续跑。同标签两单，比较引用与未引用的文字回复。
3. 三家真实客户端测可见样式、接收、按钮与表单回调、原卡更新、文字抢先提交。另验证飞书扫码新建、钉钉第二组织不配模板，以及企微包含填空时的文字回退。
4. 飞书与 Web 确认投递分别验证只写一次、仅对收件人可见、不触发。模板不可用、发送结果未知和卡片更新失败三类分别检查。

## 测试分支验证与渠道限制

- 点击后更新与文字先答后的主动更新分开验收。飞书按原消息 ID 更新，官方接口回读确认完成态且没有提交按钮。钉钉用同一 `outTrackId` 主动更新审批卡和表单卡，厂商确认成功，手机端显示另验。两家都不补发新卡。
- 企微机器人长连接主动发卡的回执不能用于替换原卡；官方的更新动作需要本次卡片点击的回调标识。文字先答仍立即结单，旧卡再点时只展示既有结果，不重做确认。
- Web 回写覆盖确认人未开过对应私聊时不创建会话、确认挂起后只向现有确认人私聊写一条系统 Input，以及不创建模型轮次。与发起人的拒绝结果通知是两条独立路径。
