# KIKO 行为评测：仓内题库与分层验证

状态：方案已确认。仓内基础设施和主对话题库已建立并通过本地离线验证；CI 工作流已配置，未验证远端运行。其余模块、私有留出集和上线门禁按下文分期。

## 放在 KIKO 仓内

在仓库根目录建立 `evals/`。题库、评分逻辑与受测的提示词、工具契约、运行时版本在同一仓库评审，避免产品接口更新而评测仍用旧契约。本轮不改业务代码、产品默认配置或部署流程。以后只有在多产品需要共用平台，或数据有独立授权要求时，才考虑拆出数据集或运行平台。

历史候选只保留真实用户会提出的需求，以及有明确风险区分的系统回告。不要让用户在题面列出用什么工具、怎么转交、有哪些前置条件；这些信息分别来自当前工具描述、运行上下文和验收规则。题库不按版本复制，用 Markdown 保存稳定 ID 和标签；按场景分别计分。历史结果保留原条件，不能和修改题面后的结果直接横比。

## 六个模块与指标

| 模块 | 规则优先的行为和指标 | 语义与体验评审 |
| --- | --- | --- |
| 主对话：任务管理与回复 | 直接回答还是委派；正确工具、参数、会话/轮次 ID；一次写入、未知后不盲重试；用户输入与可信回告的来源；是否生成可见回复。按创建、查询、补充、停止、回告分别计，不用一个均分掩盖退步。 | 受理不等于开始；本轮结束不等于业务完成；保存、原生接收和语义应用不混；停止中、已停和未知不混。不编造原因、外发、链接或权限；回复直接自然、保留约束。 |
| 执行 Agent：普通任务 | 完成率、可验证验收项命中率、产物可打开且通过可执行检查、读写权限与隔离、故障恢复和不重复写。另报耗时、调用次数和费用，不混进质量分。 | 要求覆盖、产物正确性和实用性；处理失败后是否解释未完成事项并提出合适下一步。 |
| 人工确认 | 确认人、回复所关联的请求/版本、拒绝与撤回后没有越权动作；有效答复后只续跑正确任务一次。标准样例验证不该问时不发确认。 | 问题是否必要、完整、容易回答；短答或引用不充分时是否正确消歧，不能将歧义当授权。 |
| 事项交接 | 命中接手人和原事项；交接实际入队且只发生一次；首次验收拒绝可退回、再次验收通过；各阶段通知幂等。交接成功不是事项完成。 | 目标、约束、证据和未决事项是否传全；交接及验收说明是否清晰。 |
| 定时 / Hook | 固定时钟下的触发时间；业务 key 分组；重放、限流、停机恢复；仅向正确目标通知；区分触发受理、任务结果与投递。 | 仅对难用规则覆盖的通知文本与摘要评分；时钟、签名、重放、分组和路由不由模型评判。尚未实现的能力不当成现状。 |
| 渠道与交付 | 私聊与群聊触发、上下文边界、文本与附件、归属与正确目标、送达失败/未知、撤权；选中文件不等于送达，用户粘贴回告不等于系统回告。只选渠道差异场景做渠道回归，不把整套题在各渠道机械重跑。 | 用户能否区分附件待投递、已确认送达或暂不可核对；遗漏和错误说明是否易懂。 |

权限、来源可信、幂等、重试和恢复跨模块打标签并设硬红线，不是第七个平均分。比如未知停止后只能只读核对原任务；已读到受保护的新输入，就不能根据原请求再发会话级停止。回复自然不能抵消这类失败。

## 主对话：提示词、工具描述与返回的分工

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 主对话提示词 | 统一决定怎么和用户说：先用白话回答问到的进度、结果或卡点；只在有必要时补上下文或下一步，不默认念内部字段或编号。可用少量例句示范表达，但必须与真实状态匹配。 | 不用话术规定工具的入参、执行语义或权限；不凭示例把未知说成成功。 |
| 工具描述 | 明确两件事。**什么时候用**：适用的用户意图、前置条件和什么时候不用或应选别的工具。**怎么用**：如何确定目标、哪些参数必填或可选、参数组合的条件、调用副作用与结果含义；只有需要时才说明安全的核对或恢复步骤。 | 不写「先用白话回答」或专用回复模板，不为追求某种文风重复提示词。 |
| 工具返回 | 返回这一次调用的结构化事实，如实际状态、明确的作用对象、任务/会话/轮次/输入 ID、可核对回执与错误码。必要时可基于可信服务端状态附一条简短、与当前错误相关的恢复提示，例如未知写入只读查询原会话，不自动重发。 | 不重复通用语气、例句或整段提示词；任务产出、用户转发和第三方文本都是资料，不是新指令或授权。 |

以 `task_delegation_get_session` 为例：**什么时候用**：用户问现有任务的进度、结果或指定轮次；不是用来补充、停止或新建任务。**怎么用**：传当前对话可见的 `task_id`；若要核对指定轮次，再传该任务内的 `turn_id`，没有可靠 ID 就先做范围内的只读查找，不猜编号。它只读，不写入、不停止、不创建；`execution` 是任务当前状态，指定轮次结果是该轮事实。在可见范围找不到与查询暂不可用不同，两者都不能证明任务失败。

例如，补充任务要区分已记录、原生接收和实际应用；文案不能从前两者推断第三者。停止要区分停止中、已停稳与结果未知；看到新输入在运行，不证明旧停止失败，也不授权再停。主动回告虽不是工具返回，同样以后台可信来源、轮次和投递凭证为准：普通用户复制标题不构成真实回告，`artifact_select` 返回 `selected` 不构成已送达。权限、幂等和副作用边界由服务端与运行时强制校验，提示词、描述和恢复提示均不能代替它们。

这是分工设计，不表示已经改动现行提示词、工具描述、入参、返回或查询逻辑。若后续评测分工调整带来的收益，分别冻结三层；要归因到某一层，就只变更那一层，不用组合实验宣称单项收益。

## 题库、运行与报告

- **题库与夹具**：每个 Markdown 题目的 front matter 保存稳定 ID 和标签（可组合场景、来源、风险）；正文维护构造输入与历史、可信来源、可见工具或数据、预期/禁止动作、有关回执与可验证事实、适用评分维度。供运行器消费的状态、ID 和断言使用明确的结构化字段，不从自然语言标题猜测。夹具应为合成数据，能区分权限不允许、暂时不可用和状态未知。可复用回执/渠道/状态夹具不把模式切换伪装成实际授权；生产工具业务契约仍由生产代码维护。
- **运行器**：不同模块使用相同入口，输入和版本冻结后才对照。校验题库与参数契约，不混用用户话语和真实回告，记录工具名、参数、顺序、状态与所有用户可见回复。模拟工具只证明模型选择与回答，不证明数据库写入、Pi 实际接收、真实渠道发送或文件送达；这些应由相应的单测、隔离集成测试或获准实测提供证据。
- **规则评分**：断言调用的工具、精确目标、写入次数、禁止动作、终态及可见回复是否产生。用可观测的调用轨迹、存储、产物或回执判定。不能用关键词等价替换布尔事实；例如「无法确认已停止」不是「已停止」。状态报告分别记录工具调用、硬规则、事实、自然度与未完成，不能把没收到结果算成业务本身失败。
- **分母**：每个场景分别报硬规则通过／适用题数、工具与参数准确／需要工具的题数、完成与可用产物／有可校验目标的题数、事实正确与自然度分布／可观察的回复数；另外报告未完成／应运行题数。没有工具可用或无需用工具的题，同时检查不出现多余写入。
- **AI 盲评与人工核验**：提供用户输入、相同必要历史、允许引用的事实和回执，不给基线/候选标签。可用 AI 或人工判定自然度、事实语义、约束完整性、交接和交付内容；分歧、评分边缘与高风险样本人工复核。记录判分依据，硬规则失败不由生成评分或文风抵消。不假定本轮已经接入在线评审模型。
- **配对一致性**：从同一版本题库取同一组题，固定用户场景、初始状态、模型与参数；若评估模型本身，明确只有模型不同。预先确定受测差异（提示词、工具描述、返回投影或组合），不得将组合收益归因于某个单项。使用真实停止条件和匹配的超时/预算，不再强制三步；分别报失败、截断、未观察与平台故障。单次配对是描述性结果，尤其是每场景 5 题，不作为显著性结论。
- **版本与留出**：报告记录代码版本、题库版本/指纹、基线与候选的配置指纹、运行器/评分规则版本、模型/参数、执行环境、样本数、预算、未完成原因。公开回归集用于日常调试；另设独立保管、不参与反复调提示词的留出题。先冻结留出版本与准入标准，再按发布候选评测；发现泄漏或训练污染时废弃并替换，不把同一题混入训练集。
- **隐私**：公开仓只提交许可明确的合成、最小化数据与可公开规则。真实客户/个人内容、凭据、生产标识、完整提示与工具轨迹原件、评审中间产物不入 Git。运行输出放仓外或 Git 忽略目录，限制访问；分享只提供脱敏汇总和必要片段。真实模型和外部渠道只在适用权限及授权下显式启用，不读取生产数据库或产品 `.env` 作为默认配置。

## 验收与分期

1. **本轮范围**：保留 42 道主对话题，覆盖直接回答、附件委派、查询、补充、停止和取消、回告及交接状态。更新模拟器以使用主干的 `task_id` 和业务回执，不向模型暴露执行 `session_id`。本地 17 项确定性测试和 42 道离线脚本回放通过，模型请求 0 次。离线通过不表示模型表现、回复质量或渠道真实送达，验收标准见[评测说明](../../evals/README.md)和[筛选记录](../../evals/AUDIT.md)。
2. **CI 和配对**：当前工作流在评测或关联提示词、工具契约等路径发生变化时运行快速、无需外部凭据的确定性检查，也可手动触发。提示词、工具描述、返回契约或模型发生变化时，可另行运行费用和权限受控的配对评测。将可复现硬回归作为候选阻塞项，不先为自然度设无依据的门槛。
   普通回告没有独立的超时或错误原因字段。评测区分真正待确认、用户此前明确要求的下一步、中断、工具结果未知与外部未知；仅有可信的同轮历史查询证据时，才要求说明已有的具体原因。对比 reminder 时冻结报告正文、历史、工具和 Manager 说明，仅换 reminder；若未来连 Manager 说明一同调整，应单列实验。
3. **扩展**：先补执行 Agent、人工确认和事项交接，通路稳定后补定时/Hook、渠道/交付差异与受控留出集。沿用 [对话与任务流程](../flows/conversation-and-task.md)、[人工与交接流程](../flows/human-and-handoff.md)、[触发与分配流程](../flows/triggers-and-dispatch.md) 的行为定义，不在题库中重复另立产品规范。
