# 平台服务配置迁入数据库

状态：已实施，现行行为见[模块 Spec](../spec/platform-service-settings.md)。使用本地夹具和自动化验收，不连接真实 SMTP 或 OAuth 账号。

## 范围

- 启动与部署依赖（数据库、服务互连密钥、持久存储、公开 Origin、可信代理）继续由部署提供。测试专用 `DEEPSEEK_*` 不放在部署示例。
- 在「设置 → 平台管理」提供两类实例配置：邮件发送与邮箱注册策略；GitHub 插件 OAuth 应用。平台管理员才可读取或写入，仍由后端独立鉴权，不需额外页签 env 开关。
- 已有官方模型、积分、平台角色沿用原实现。网站第三方登录、扫码注册和账号绑定是独立能力，不借 GitHub 插件设置开放。
- 老部署无对应数据库记录时，沿用旧 env/JSON 生效值。显式保存后，数据库记录完整覆盖该类配置；禁用不回退。迁移需明确由管理员保存，不由启动过程自动写入。
- 秘密经用途隔离的应用加密后存储，不通过读取接口返回，不写日志。修改需匹配版本；失败不替换当前已生效配置。新设置由所有 Backend 副本从同一数据库读取。

## 计划验收

| 场景 | 预期结果 |
| --- | --- |
| 新库无 SMTP，不提供旧配置 | 默认可密码注册和登录，邮箱验证码与邮件邀请不会开放 |
| 旧 env 可用，导入并保存禁用 | 迁移前继续正常；DB 保存后所有副本关闭邮件，不回退旧 env |
| SMTP 试发失败或生效后 SMTP 暂不可用 | 失败不写入配置、不放宽既有注册策略；试发仅触达当前管理员的账户邮箱 |
| 更新密码与并发保存 | 保留旧密码或显式替换，读取始终不带明文，旧版本不能覆盖新保存 |
| GitHub 应用禁用、轮换或期间回调 | 关闭不回退旧 env；新授权使用新配置，进行中的尝试不会混用新旧凭据 |
| 普通用户、工作区管理员直接请求平台接口 | 后端拒绝；仅平台管理员可访问配置 |
| 数据库不可读或秘密无法解密 | 相关操作失败，不伪造旧值、静默降级或改动平台角色 |
