# 本地启动器移除 Python 依赖

状态：已实施。macOS 真机完成首次启动及启停，macOS/Linux 均完成黑盒回归。现行行为见[本地启动器 Spec](../spec/local-launcher.md)。基线：`2c71b9c` 的 `start.sh`、`tools/local.py` 和 `tools/docker_support.py`。

## 范围和方案

- 以可移植的 POSIX `/bin/sh` 实现 `./start.sh`，Docker 安装和命令监督单独拆分。日常自托管启动不需要宿主机 Python，也不新增 Bash、GNU coreutils 或第三方运行时要求。原生开发入口 `tools/runtime.py`、契约校验、Engine 容器中的 Python 不动。
- 保留默认启动、`up`、`init`、`status`、`logs`、`down`、`restart` 和 `--update` 的行为。更新只允许快进，失败不停止旧服务；更新成功后执行新版入口。先构建，再停旧 Engine 和 Hub，再等数据库、Backend 和 Hub 就绪，再同步目录、启动 Engine。保留阶段日志、超时、错误退出及中断处理。
- 保留配置路径、格式及默认值。逐行解析并验证 dotenv，禁止 `source`、`eval` 和变量插值，不在日志中回显值。沿用现有指纹输入的字节序列和算法；已有 `.env`、令牌、数据卷和状态目录不迁移、不覆盖。继续拒绝缺配置但有旧数据、旧部署混用、凭据变化和不安全文件。用原子文件发布与同仓库互斥保护；异常中断后仅在确认旧启动流程不再运行时回收锁，无法确认则发出恢复指引，不抢锁、不删卷。
- Docker 安装引导完整保留：Linux 受支持发行版走官方 apt 源，保留冲突包和旧源检查、管理员授权、签名密钥及非交互拒绝；macOS 保留版本与架构判断、旧兼容版 SHA256 校验、空间检查、打开安装镜像与等待 Docker Desktop 就绪。仍由用户明确确认，不静默提权、授组、放宽 socket 或接受许可。
- 用同一套黑盒用例覆盖 macOS 和 Linux。真实启动使用新 checkout、独立 Docker 项目/卷/端口/存储目录；隔离只改变测试资源标识，不改变用户入口及默认资源名称。测试期间不对本机执行真实 Docker 安装，不碰现有实例，不推送。

## 验收用例

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| START-01 | 已装 Docker 的隔离机器，在启动路径找不到 Python 的情况下运行新 checkout 的 `./start.sh` | 无手工配置；四个服务健康，Hub 完成迁移，目录同步，Engine 注册，Web 与注册 API 可访问 |
| START-02 | 在新版首次启动后创建账号，再执行 down/up 和使用本地 Git 上游的 restart | 配置、令牌、指纹、账号和工作区保留；down 完成后停止容器，不删卷。旧版指纹与入口兼容只跑夹具 |
| START-03 | 缺 .env 但存在旧卷/状态、凭据变更、不安全权限或链接、歧义 dotenv、错误地址 | 拒绝启动，不覆盖文件、不停旧服务；旧版可接受的合法配置仍可读 |
| START-04 | 并发运行 init/up，以及取消或注入超时 | 不争抢写入或并行操作同套容器；退出码和诊断明确，不残留继续执行的子命令；没有确认前不接管陈旧锁 |
| START-05 | 构建失败、快进失败；检查默认 up、update/restart、status/logs/down | 失败时旧服务保持；默认 up 不拉取；各命令动作和顺序与旧版一致 |
| START-06 | 模拟 Linux/macOS 平台命令，覆盖 Docker 缺失或未就绪、非交互、拒绝、冲突和兼容校验 | 官方安装引导和确认策略保留；不触及真实系统安装或现有数据 |
| START-07 | 运行全部原启动器用例的等效测试，并做独立文档审阅 | 不丢有效断言；README、部署指南、CI 与正式 Spec 同步更新；区分真实启动、模拟安装、未验证平台 |
