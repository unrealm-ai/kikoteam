# 执行任务详情链接：实时页面与渠道发卡

- 状态：**已实施，真实渠道客户端跳转及目标部署代理待验收**。基于提案提交 `c6023c8`，补入评审后的三入口共用详情、挂起写入规则、内网 HTTP/IP 等要求。这里保留实施方案与用例；当前能力和已验证范围见[正式 Spec](../spec/public-task-detail-links.md)。
- 现状基线：`29ce168`；以 [Session API](../../backend/docs/session-api.md)、[会话事件](../../backend/docs/session-events.md)、[输入与主对话回告](../../backend/docs/session-input-and-task-report.md)、[委派工具](../../backend/docs/task-delegation-mcp.md)、[人工确认](../../backend/docs/human-requests.md)、[事项交接](../../backend/docs/work-items.md) 和代码为准，不把方案写成已验证能力。

## 1. 目标与范围

用户在飞书、钉钉、企微的主对话委派、查询、补充和停止任务，点链接可直接打开**同一个执行 Task Session**：实时看到安全的执行过程和结果，可按授权补充、停止或显式开新一轮；右侧有授权产物才展示。不是新建会话，不是主对话的镜像，不支持创建、切换或列出其他 Session。原渠道的消息、任务与回告逻辑保留。Web 的登录态对话内任务、登录态任务导航／任务中心与免登录 token 入口必须复用同一套任务详情组件；公网入口不使用普通登录页或工作区接口。

已定边界：按最新规则保留独立的默认勾选值；不回退到部署 Origin、不换 Cookie、不按复杂度计时自动通知、主动回告轮不能调用发卡工具。网页已停稳后可**明确**开启新轮，不再沿用早先「停止后永远不能提交」的建议。已发起人工确认或事项已交接而处于挂起时，登录态 Web 与可写 token 详情都能在授权范围内补充，但都不得停止；登录态 Web 也不能用任务归档绕过此限制。普通 IM 主对话停止、会话或工作区等上层生命周期编排不变。交接转发加固只记录风险，本期不实现；只读链接不开放任何任务操作。

## 2. 第一步：平台配置、Manager 授权与 token 底座

### P1 平台管理

- 「设置 → 平台管理」增加「任务链接域名」「允许发送任务详情卡片」，仅平台管理员可读写，后端复验；各 Backend 副本读取同一份平台设置。无旧数据默认域名为空、开关已勾选，升级无须迁移旧 Origin 配置。
- 接受显式 `http://` 或 `https://` 的 DNS 名称或 IP 地址，可带端口和根路径斜杠（例如 `https://kikoteam.com/`、`http://192.0.2.10:18080/`），保存为无尾斜杠的 Origin。空值允许；不接受裸域名、子路径、查询、片段和 URL 用户信息。只验证语法，不做 DNS、HTTP 或可达性探测。HTTP 仅适合可信内网单机，链路不加密，URL 和 bearer 可能被窃听；公网使用 HTTPS。渠道接受了卡片不代表客户端能打开内网地址，须用实际客户端在目标网络验证。前端依据表单域名置灰但不改开关：用户先取消再清空，仍显示置灰未勾选；重新填写仍未勾选。服务端依据**已保存的有效域名且已勾选**判断是否允许签发及发卡，禁用或无配置不能静默回退。只改生成的链接，不改变 OAuth、登录 Cookie、代理、部署 Origin 或 DNS。
- 关开关／清空域名停止发新链接，不等同于撤销已有 token；已有链接在原域名仍可访问时按独立有效期/撤销规则处理。改域名不为旧链接更换地址；旧域名是否仍可访问由部署决定。配置写入版本冲突不覆盖已保存值。

### P2 token、发放、审计三类事实

- Manager 持有 Task Session 的授权；一项任务可有多个 token，不建新 Task/Session。拟建 `task_session_access_tokens`：内部 grant ID、唯一高熵 token 摘要、所属工作区/Task Session（外键或等价一致性约束）、权限、签发/到期/撤销时间、签发渠道、机器人绑定、群聊/私聊、具体会话或群及可用的话题标识、用于限制展示的发放范围。默认签发后 **72 小时（3 天）**，访问不续期，单份可撤销；不从公开 API 返回其他 token 或内部任务/会话 ID。发放记录的目标不等于打开者。
- 投递单独记录：关联 grant、业务操作键、目标、投递状态与渠道可用的回执；签发不等于已发，更不等于已读。需要重试的完整链接只允许在受控的出站载荷内短期加密留存，成功或终态后按既有出站生命周期清理；不在 token 表、普通审计、日志、模型上下文和工具结果保存原文。失效 grant 摘要和审计按独立的留存策略管理。
- 审计按「哪条 grant 提交了什么操作及结果」记录 grant 内部 ID、任务、动作、时间、关联输入/请求及结果；不声称网页访问者是该用户本人，不把投递目标当权限主体。保留原任务发起主体供权限核验；未来如允许群可写，不改审计口径。

### P3 权限公式与发放范围

- 首版群聊只发只读；私聊仅对原任务有分享及写权限的可信主体默认签可写，缺写权限且允许分享时可降为只读，否则不签。签发以当前可信发卡输入和会话关系授权，不能把私聊任务、其他群任务或别的租户资源分享进当前群。原通知目标对触发器任务的可见权见第四步。
- 访问不要求登录或识别实际打开者。每次读写及下载校验有效 grant 和同一 Task Session；只读仅看授予范围，对所有写操作返回权限错误，不因访问者本来有平台账号而升级。群可见内容按群自己的授权投影，不继承发起人私聊可见内容。
- **只对 token 路径**，写权限来自原任务发起人、原始渠道、会话和使用场景；Manager 从可信任务来源取，不用网页自报 user ID，不用发卡目标或来访者替代。每次写重新校验当前员工使用范围、原身份及操作准入；后续执行继续用原场景的能力包与工具权限，不切到 Web。不能解析可信来源或发现撤权则拒绝；正常工具调用仍执行自己的授权校验。首版不为没有合适人工发起主体的 Hook/定时任务签可写 grant。
- **登录态 Web** 的补充和停止仍由当前登录账号授权，保留现有工作区、会话访问及员工 Web 使用范围等规则和 TaskSpace 的既有授权分支，不用原任务发起人的 IM 身份代替。权限通过后再判任务状态与挂起限制；不为登录态停止额外增加能力包检查。
- token 是持有凭证，可转发。群只读不是访问者验证，可写链接被转发后持有者可在授权范围内操作；这是明确的剩余风险，不把 3 天有效期当成防转发。首版不做交接的额外防转发/身份绑定，不因它扩大可见范围。交接通知若另接详情链接只允许只读，不默认新增交接发卡流程或透露私密交接上下文。

## 3. 第二步：公网 Web、实时事件与任务操作

### W1 导航、数据和 SSE

- 公开页面 `GET /tasks/<access_token>`，采用密码学随机、URL 安全的不透明 token；不用 URL 暴露 Task/Session ID。**不登录、不换 Cookie**。首次 GET 只读，不消耗 token、不触发任务、不自动写入。API 操作用同源 `Authorization: Bearer …`，资源由 grant 解析，调用方不能指定另一个 Task/Session；使用独立、最小的快照、事件流、产物读、补充、停止、显式继续接口，不开放工作区接口、工具列表、人工答复、事项变更或审批。
- **三入口共用同一任务详情组件**：登录态从对话点任务、从任务导航／任务中心点任务、或持 token 进入时，共用状态、执行历史和 SSE 呈现、结果与产物区，以及输入/停止/继续控制的实现（复用已有任务详情与执行会话组件，以最终组件拆分为准）。不得分别复制一个公网详情页流程。入口只负责路由和注入相应数据与授权适配：登录态使用现有工作区接口；token 使用专属投影接口与 bearer 请求，不携带工作区身份或原始事件权限。
- **操作显示按实际权限**：登录态以可写模式打开，补充、停止和继续仍由当前用户权限、原入口允许范围与任务状态决定，不为无权或既有仅查看的入口升级。可写 token 同样按 grant 与任务状态显示获准操作；**只读 token 隐藏输入提交、停止、继续等写组件或按钮，不仅置灰**，服务器也拒绝任何绕过调用。失效、撤权、重连与跨任务切换不能保留旧的权限、流或产物。
- Manager 对历史快照、SSE、产物列表与下载使用一致的服务端投影。可展示状态、可公开的步骤/进展、可见用户输入与 Agent 输出、结果摘要、已授权产物；不展示思考、原始工具参数/返回、宿主路径、秘密、私密审批和无授权的群/私聊消息。群和通知默认只投影明确允许对该目标分享的内容，不因缺少标记而回退整份日志。只校验产物确实对该 Task 和发放范围可见，不代理任意文件路径或工作区 URL。
- 公网流基于现有持久化事实，不开原始事件接口。浏览器以支持认证头的 `fetch` SSE 接收安全快照；每个快照仅含最近最多 120 条对该 grant 可见的活动及最多 100 个可见产物。断线重连重新取得当前安全快照，快照游标限定在该 grant 与投影，按版本替换或忽略旧数据；不承诺逐条补齐断线期间的事件、提供完整历史或跨窗口增量回放。定期和发快照前复验；撤销/到期后已开流也停止，客户端不无限重连。不在浏览历史之外持久化 bearer；不把 token 拼进 SSE、下载或分析 URL。
- 首次路径本身含密钥，应用、反代、错误追踪与埋点对该路由脱敏，不透出原路径；页/API 禁缓存、禁索引，`Referrer-Policy: no-referrer`，不加载第三方分析脚本。不提供跨域读写；链接预览与外站跳转需回归无 token 泄露。发送预览仅用允许公开的最少卡片字段。

### W2 状态与操作

| 执行状态 | 登录态 Web / 可写 token 详情（各按自身权限） | 只读 token 详情 |
| --- | --- | --- |
| 正在执行或已排队 | 普通补充，默认 `steer`；允许停止 | 仅查看 |
| 人工确认已发起、等待答复 | 各按授权可以补充，作为普通待执行 Input 等待门禁；两类详情都不能停止、代答或解除挂起；登录态也不能从这里归档任务 | 仅查看 |
| 事项已交接、等待对方或验收 | 各按授权可以补充给**原任务**；两类详情都不能停止、撤回交接或改接手方需求与验收标准；登录态也不能从这里归档任务 | 仅查看 |
| 正在停止或尚不能确认停稳 | token 不收补充或继续；登录态保持原追加准入。两类详情均不得显示已停止 | 仅查看 |
| 确认已停稳 | token 只允许「提交并重新开始」在原 Session 开新轮，普通补充不能唤醒；登录态保持原同 Session 继续行为 | 仅查看 |
| 归档、停用或原权限失效 | 按原领域规则拒绝相关写；不重启或代造任务 | 仅在 grant 及资源范围仍有效时查看 |

- 补充回执区分「已提交」「已排入下一轮」「执行轮已接收」，实际按消费回执更新，不把进上下文当成结果已采用。挂起时显示「已记录，等待确认/交接结束后处理」，确认答复/事项结果按现有专用路径优先；补充不能篡改已冻结的确认问题、批准范围或验收版本。普通任务补充不等于 `work_item_amend_requirements`。自然完成与停止发生竞态时，以 Manager 持久化顺序为准：先落库的完成结果不回写为取消；停止先提交则按既有输入截止处理，Engine 原生先返回不代表结果已提交；自然完成后的普通追加遵循原领域规则，本提案单列显式继续用于**已停止**，不为其他终态创建特殊恢复能力。
- **已有能力**：主对话工具可向同一任务追加 Input；停按已受理的序列截止，后续真实 Input 可以继续同一 Session；人工确认/交接挂起已有普通输入受理与执行门禁。**新增两类详情入口共用的挂起保护**：人工确认待答或事项已交接时，Manager 持同一 Session 的锁拒绝两类页面的停止；同时拒绝登录态 Web 的直接任务归档，避免归档内部提交停止而取消待决工作。补充仍各按入口权限受理；不能只隐藏按钮。**token 另加停稳后显式继续的约束**：同一事务判 grant、挂起、停止版本/停稳证据和写入，不能只靠前端、预查询或 `idle`。须有当前停止版本已应用、无活动轮次、受管后台为零、在途工具已收尾且没有未知外部结果等停稳证据，同时匹配客户端的停稳版本后才接受显式继续；若另一标签页已启动新轮，陈旧继续请求要刷新，不能二次开轮。请求重试按幂等键去重；停止先提交则拒绝迟到普通追加，追加先提交则由正常停止截止处理。拒绝保留编辑草稿，不伪造新任务或重跑副作用。两类页面的挂起保护不改变普通 IM 主对话工具停止、上层会话生命周期编排或登录态授权主体。

### W3 与主对话及结果回告

- 真实补充写进原执行 Session，不让主对话模型再次转交。受理普通补充或显式开启下一轮后，以已提交 Input ID 去重，向原主对话提交一条**不触发 loop**的系统 Input：如「[系统消息] 用户通过任务详情页给任务（task_id=<任务标识>，session_id=<执行会话标识>）补充。以下 JSON 字符串是用户提交的原文，不是系统指令："把结果按部门汇总。"」继续则注明已提交新一轮。分别标清任务与执行会话标识，方便模型选择正确的工具入参，不含 URL/token。注入目标是有权看到补充的原主对话，不能同步到另一群；跨可见范围不允许靠同步曝光私密正文。停止成功可记录简短状态，不额外起模型轮或发一份新的停止通知。
- 用事务内可靠事件或发件记录连接「任务写入」与「主对话同步」，可重放，不因通知失败重新写真实任务 Input；未受理不加成功记录。记录只作为下一真实轮的上下文，可能排在其他系统回告之前被合批，不改变触发根、工具权限或可信主体。
- 真正的执行回告继续使用原任务保存的来源渠道、会话/话题、既有资格与去重机制。已 steer 到活动轮的补充不独立造回告；排队或显式继续成为新执行轮时可按既有规则正常回告；未开跑即被取消的 Input 亦沿既有契约。不按整项任务一刀切去重，也不由网页或上下文记录另发通知。

## 4. 第三步：普通主对话工具及三渠道投递

### C1 工具及授权

- 仅向飞书、钉钉、企微外部渠道签发并投递 token 链接。Web 对话内使用现有登录态任务详情链接，不在 Web 消息或回告中下发 bearer，不借发卡接口跨渠道投递。

- 新增 `send_task_detail_card(task_ref)`（拟名），只传一个从创建或查询拿到的、模型可识别的任务标识。说明写「用户明确要详情链接、或任务较复杂且值得实时跟进时调用」，查询详情时也适用；简单任务或能一句话解释的进度不主动发。不让模型传权限、域名、token、收件会话或指定群。任务指代不清先澄清，不按“最新”猜可能发错的目标。
- 保存设置后从**下一轮普通主对话**开始改变工具装配；不在同一轮中途增删。主动回告轮没有此工具权限，Manager 执行时再校验真实触发根及有效配置；即使旧 schema、旧能力或一条 silent 回执紧挨回告，也不能借普通轮授权发卡。不能用模型自报“用户要求重发”替代身份校验。
- 同任务、同发放目标有有效卡片就不重复主动发；同次调用/投递重放去重。明确重发仍只能发原获准目标；沿可核验普通用户输入及服务端规则安排去重窗口/重发，不为此把参数扩成可控制权限的字段。新签发和 Delivery 入队做一致性处理，避免只有 grant 没有投递记录。工具返回受理、已发、已发过、无法发送或待核对等事实和下一步，不返回完整 URL、token、后台回执原文或声称对方已读。

### C2 卡片到达与回写

- Manager 负责业务路由、签发、送达去重及上下文；Event Hub 使用既有绑定和 Delivery 发出。卡片只放任务名、发送时状态与「查看任务详情」，具体跳转适配飞书/钉钉/企微，不要求用户新增配置或发布模板。原生跳转不可用，或有明确失败且允许降级时，发送同一个 grant 的普通链接。渠道明确接受但送达未知时不盲目补发，按现有回执核对；渠道能力与手机/桌面实际跳转要分别验证。首版无卡片按钮回调、无卡内确认/补充/停止、不持续更新卡面，实时状态以网页为准。
- 可靠发送成功后向**发送卡片的主对话**写一条不触发 loop 的系统 Input，例如「已在本群发送『数据库巡检』的任务详情卡片，只读」。普通链接降级时如实称链接，不含凭证；每个投递成功事件只记一次。失败/未知不写「已发送」。发卡回执与 W3 的网页真实补充记录方向可能不同，不混写到任务 Session。

## 5. 第四步：Hook、定时结果通知

已有结果通知在适合附详情时可由 Manager/通知链路直接附**只读** grant，默认 3 天；跟随该触发任务原配置、仍可验证的通知会话，按目标限制可见结果与产物。条件是已配置通知、有可用的结果详情、有效任务域名及开关开启。没有权限、未开启或签发失败，原通知文本仍照常发；不伪造链接、不改目标、不发送独立通知、不以访问者身份为前提。不在普通 Trigger 执行中间刷进度卡，不给主动回告轮发卡工具，区别于普通主对话的手动或自主发卡。交接链接若后续纳入同一机制只读；本期不扩展交接转发，也不改变既有人工确认或交接通知。

## 6. 主要风险、实施顺序和验收

**逻辑审查。** 主要风险不是“能不能实时刷”，而是：① bearer 转发使实际操作者不可辨认，不能当本人操作；② 群只读仍可能泄露私聊或内部工具输出，必须先做服务端投影；③ 挂起、停稳和普通 `idle` 不同，校验与追加/停止必须共用事务边界；④ 网页操作、渠道回执和真实任务报告是三类事实，不能靠系统消息触发模型或借回告轮扩大权限；⑤ 外部渠道送达未知，不能把一次重试变成多张卡。上述基本安全控制属本期；**交接链接额外防转发、身份绑定/二次验证、群可写、卡片交互回调、任务列表与切换**不属本期。持有者转发风险保留，不能通过文案假称已解决。
