# Hook／定时任务结果回告：卡片优先

- 状态：已实施；Event Hub 与 Manager 隔离 PostgreSQL 自动化通过，真实渠道客户端待验。见[正式 Spec](../spec/public-task-detail-links.md)。
- 基线：[任务详情链接方案](public-task-detail-links.md#5-第四步hook定时结果通知)；本次只调整具备详情链接的 Hook／定时任务结果回告，不改普通主对话发卡。

## 行为

1. 原通知可以附只读任务详情时，飞书、钉钉、企微优先发送一条原生详情卡片：保留原回告文字、结论和必要换行，另加「查看任务详情」按钮。用渠道支持的安全格式承载原文，不用摘要、通用状态或任务标题替换。不能完整承载时不发送截断卡片。
2. 发送前能确定卡片不适用，或渠道明确拒绝卡片、确认未发出且允许降级时，改发**原回告文字＋同一个详情链接**。渠道已受理、回执未知或无法查证时，按原链路核对，不补发链接或重跑任务。无可用链接（如开关关闭、签发或授权失败）时，照常发原回告文字。任何增强均不能截断原文、改发目标或新增独立通知；若连链接都不能安全附带，保留原回告。
3. Web 保留原文本通知和静默 Input，不下发 bearer，不新增 Web 群界面、入口或权限。飞书仍按群／话题真实投递锚点补历史：先补近期群消息，再将结果写入对应员工会话，`trigger_agent_loop=false`，沿用结果 `source_kind=task_result` 和 `[系统消息]`。确认实际发出卡片或兜底链接，统一写「[系统消息] 已发送任务结果，任务详情链接可查看。」并保留原正文；纯文本通知不加该说明。记录只取已持久化的回告文字，不带完整链接、token 或卡片原始载荷；未确认送达或不能可靠校准锚点，不伪造记录、不推进历史边界。钉钉、企微既有历史限制不变。

## 实现边界

- Manager 复用现有 Trigger 通知身份、同一只读 grant、尝试凭证和权限；Event Hub 按现有适配器渲染卡片，并在同一通知流程内确认实际投递形态。回执与原通知目标／尝试绑定，重放不得另发消息或重复入 Input。滚动发布期间，未声明新能力的 Hub 仍能走原回告路径。
- 飞书卡片以可信发送回执记录锚点，并按消息 ID 回读原生卡片复验发送应用、群／话题、时间与供应商确认的原生卡片类型（不解析卡片正文或 bearer）后才能充当历史锚点。不放宽普通文本或链接锚点校验，也不以本地时钟或卡片标题代替。卡片链接仅供获准目标展示；上下文、日志和公开测试材料不得含真实 bearer。
- 不扩大已可附详情的结果范围，不改原任务终态、固定定时提醒、人工确认、事项交接、普通主对话发卡或现有详情页权限。

## 验收

| 编号 | 场景 | 预期 |
|---|---|---|
| TRC-01 | Hook／定时已完成，各渠道有可用详情；原回告含中文换行、Markdown 标记或用户数据 | 外部渠道实际卡片保留原回告内容且单个详情按钮打开同一只读结果；Web 原通知不变、不出现 bearer；没有第二份通知。 |
| TRC-02 | 卡片不适用／明确拒绝，或已受理后超时；另测关闭设置、无权限、超长正文和旧 Hub | 可安全降级才发送原文＋同一链接；未知不补发；无可用链接或不能安全加链时原文仍可发；任务结果独立。 |
| TRC-03 | 飞书群和话题分别真实确认卡片、降级文本，重放回执，并注入错误话题／缺锚点 | 仅正确锚点历史后写一条本员工不触发结果 Input，只有实际卡片标明卡片；不存在 bearer／重复写／越界推进；Web 原静默行为保留。 |
| TRC-04 | 隔离数据库、三渠道适配器和获准测试客户端 | 自动化覆盖条件、投递／未知／降级和上下文；手机／桌面显示、跳转、文字保真与群／话题锚点按真实实测分别标记，夹具结果不算真实渠道验收。 |
