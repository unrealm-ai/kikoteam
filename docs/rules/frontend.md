# 前端开发

适用于工作台、配置页面、API 客户端及事件订阅。产品边界见 [web README](../../web/README.md)。

**章节导航**　[请求与页面状态](#请求与页面状态) · [列表与筛选](#列表与筛选) · [对话与任务](#对话与任务) · [验证与布局示例](#验证与布局示例)。追加阅读条件见[规则索引](../../AI_RULES.md#按任务查阅)；改变业务状态的含义或可执行操作时查阅[业务设计](../../AI_RULES.md#业务设计引用)。

## 请求与页面状态

- 页面区分加载中、空结果、无权限、失败和成功。业务动作展示服务端确认的结果；异步受理后展示可查询的进度。
- 请求和订阅绑定当前账号、工作区、资源及查询条件。切换上下文时取消旧请求或丢弃过期结果，离开页面时清理订阅。
- 客户端从提供方契约取得字段和错误码，分别处理网络错误、超时、用户取消、业务冲突和权限变化。出错时提供可用于排查的请求标识。自动重试仅用于契约明确允许重复的操作。

客户端同时遵守[SDK 和服务客户端](backend.md#sdk-和服务客户端)的错误分类、重试与分页要求。

## 列表与筛选

筛选、排序或工作区变化后，重置页码或游标。翻页沿用原查询条件；服务端连续返回同一游标时终止迭代并报告协议错误。允许用户继续访问资源的操作应以当前授权为准。

## 对话与任务

可恢复的事件订阅按服务端契约保存续读位置并去重。临时展示数据与已确认的业务事实分开处理，完成状态依据已提交的事件或查询结果。相互独立的业务阶段分别展示，不能以一个阶段的成功推定整体完成。具体对话行为、订阅协议及状态含义见 [web 组件设计](../../web/README.md#对话与事件订阅)。

## 验证与布局示例

修改账号、工作区或筛选条件切换时模拟旧请求最后返回，确认只有属于当前页面的请求结果能更新界面；修改任务页时覆盖断线续读、报告已完成但投递失败、人工问题已被其他人处理。测试应验证用户看到的状态和可执行操作。

未来可按工作台、员工配置和任务详情组织功能，例如 `web/src/features/tasks/`。前端框架和内部路径待定，此路径仅作示意。
