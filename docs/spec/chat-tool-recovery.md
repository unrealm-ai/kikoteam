# 主对话工具的失败恢复

本规范仅覆盖任务查询、补充、停止、补充/取消待办以及回复产物选择。接口与工具集合不变。输入附件另见[入站附件 ATT-10](async-inbound-attachments.md)。

| 场景 | 模型可观察行为 |
| --- | --- |
| 任务引用不正确或无权查看目标 | 保留错误，并引导查询当前对话可见的任务列表，使用列表项的 `id` 作为 `session_id`，不猜最近的任务。指定轮次不存在时先用同一 Session 不带轮次和游标复核。 |
| 未启动或已取消待办 | 已取消待办不需要再次停止/补充。仍未启动的待办应先查权威状态和版本，并仅按原授权使用待办操作；停止请求不能自动转成取消。 |
| 版本冲突、权限失效、写入不明 | 明确版本冲突可以先读最新状态和回执，仅在确认没写入且要求仍适用时再次尝试一次；原输入主体变化或权限失效不得重试。写入结果未知先查状态或回执，查不到不是未写入的证据，不重新提交或另建任务。 |
| 产物 ID 不正确 | 当前渠道回复的授权仍有效时，可返回该回复内可选的产物 ID 与名称，不返回路径、不自动选择。只在目标明确时用完整 ID 重试一次；不能确定时继续给文字结果，不声称文件已发送。选中产物不是送达回执。 |

任务和产物的错误保留 `error.code` 与 `error.message`；有可执行引导时可附 `recovery`。候选产物为 `artifact_candidates`，只在能重新核实本轮范围时返回。人工确认工具和历史工具不在本次变更范围。

自动化：覆盖[工具恢复返回](../../backend/internal/manager/mcp/taskdelegation/recovery_test.go)及[渠道产物授权](../../backend/internal/platform/repository/channel_artifacts_test.go)，后者使用隔离 PostgreSQL。真实渠道仍需要用新消息验证送达。
