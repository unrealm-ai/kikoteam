# 人工确认卡片与答复

范围：执行任务等待指定人员确认、确认人在 Web 或渠道内答复、原卡完成态和拒绝通知。不改变任务发起人、确认人选取或交接权限。

## 题型与提交

- 发起确认的执行工具 `ask_human` 用 `type: "approval"`（不传 `questions`）或 `type: "form"`（至少一道实际问题）。要求重新审批时只允许 `approval`。候选 ID 和规则版本仍由模型按查询结果传入；Manager 按候选取范围并复验版本和收件人。旧执行端的内部请求仍可传 `decisionRequired`、`questionScope`，不改变历史数据或渠道答复。分开部署时先更新 Manager，再更新 Engine。

- 同意／拒绝使用独立的 `decision`（`approve` 或 `reject`），可不设题目。可附选填说明 `text`。可答复的 Web 收件箱提供说明框；飞书、钉钉、企微的原生审批卡不显示说明框，仍优先发卡。确认人要带说明可直接用文字回复。旧飞书卡片的说明回调仍兼容。
- 提交型支持单选、多选、文字和数字。模型提交工具每题统一传 `questionId` 和字符串数组 `values`：单选和填空恰好一项，多选一项或多项；选择题传选项 ID，数字填空传数字字符串。Manager 按当前确认单保存的题型转换并校验；Web 和渠道回调仍使用单值 `value` 或多选 `optionIds`，存储结构不变。允许单题或混合；每题独立设置是否必答。旧式纯文字题与逐项文字提交继续有效。待确认工具返回有权限的题目、选项 ID 及显示文案；文字回复有歧义时先澄清，不依赖渠道历史能否读取卡片。
- 卡片操作和文字答复使用同一业务确认事务。验证确认人、确认单和版本；卡片还核验原投递、绑定身份以及回调来源。只有首个有效答复改变状态。批准或信息提交冻结答案并恢复原任务；拒绝停止，不启动新一轮执行。拒绝说明存入确认结果；存在原发起人的可验证私聊时发一条主动通知，不向原群聊公开。

- 主私聊列表默认 `status: pending`；`resolved` 只读查询同意、拒绝、已提交表单或退回。两种状态均按确认单创建时间倒序，最新发起的在前，均支持确认编号及分页（默认第 1 页、每页 20 条，最大 50），沿用当前渠道身份和确认人权限。传确认编号且省略状态时，一次精确查待确认和已处理；明确传状态时只查指定状态，不自动选最新一单。已处理单不参与答复匹配，不能再次提交。

## 渠道与原卡

| 渠道 | 表单投递 | 原卡更新 |
| --- | --- | --- |
| 飞书 | 原生卡；纯审批仅有同意和拒绝按钮，填空输入框的组件上限为 1000。原生卡被明确拒绝而降级时记录飞书错误码。扫码创建配置包含卡片回调事件。不要求在 KIKO 手动确认，默认尝试发卡；无法渲染或飞书明确拒绝时发完整文字，送达未知不立即补发。按钮不可用可直接在聊天中答复 | 点卡可随回调更新；也可按原消息主动刷新完成态 |
| 钉钉 | 使用内置示例审批和表单模板，不要求用户自配模板。模板不适用才走文字 | 点卡或通过原卡实例更新。模板无法表达的完成态不宣称更新成功 |
| 企业微信 | 原生审批与可表达的纯选择题优先用卡；有文字或数字填空时整单发送文字 | 点击后可用对应回调更新。先用文字答时，后端先结单，旧卡再次点击只按服务端已保存的结果更新。例如先用文字同意，再点旧卡「拒绝」，仍显示「已经同意，无需再次提交」，不会停止任务或再次续跑 |
| Web | 沿用待确认收件箱及同一提交契约 | 使用服务端保存的确认状态 |

企微用独立卡片文案：题目进标题（按手机显示验收：审批最多 32 个 Unicode 字符，单选卡最多 16，多选和多下拉暂保持 26），确认编号单列；正文最多 160 个 Unicode 字符，说明保留背景、行动、影响范围和表单约束，不重复题目、选项或文字回复指引。放不下关键信息时整单回退完整文字，不截断。旧 Hub 未识别精简字段时仍可使用完整通知。

投递失败和结果未知分开处理，不能因未获得回执而无条件重发。原卡更新不补发卡片、不改变业务答复结果、不启动执行轮次。飞书确认通知成功回执和 Web 收件箱发布会向存在的确认人私聊写一次不触发模型的系统输入。发起人私聊中的拒绝结果通知不属于该回写。

## 回归证据

- [测试分支的真渠道演练](../proposal/human-confirmation-cards.md#测试分支验证与渠道限制)覆盖飞书原卡主动刷新与回读、钉钉审批和表单的主动更新接口。企微原卡替换只在按钮回调中验证。正式分支手机端完整业务流程、飞书扫码新建真实应用和钉钉跨组织模板使用未作为已通过项。
- 隔离 PostgreSQL 回归覆盖事件写入的会话范围、投递后只回写一次、不产生轮次、拒绝重放、群聊抑制、发送前权限撤回及终态卡片的版本／配置约束。Web 组件覆盖结构化作答、选填说明、已答生命周期与权限撤回。

- 企微格式回归用 296 字的完整通知和 99 字的实际审批背景，验证正常审批优先发卡；另验证审批标题 32／33 字、单选标题 16／17 字，以及正文 160／161 字的发卡和回退边界。关键信息超限或表单含填空时，仍发送未改动的完整文字。
