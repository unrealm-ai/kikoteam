# 原员工渠道页：共享群配置

真实模式在原 `WorkforceChannelsTab` 内复用按渠道配置区。非真实原型沿用原群策略控件。

- 渠道接入页此前在应用尚未绑定时也展示群配置。现在未绑定时显示渠道提示和机器人接入模块。当前渠道保存绑定后，在机器人状态下方显示对应的群配置，等待连接或已停用的绑定也适用。
- 已绑定渠道按机器人状态、通讯录同步状态、能力限制提示、群配置、白名单提示、飞书业务能力授权与具体资源访问状态排序。各渠道按实际状态显示对应模块。飞书授权明细默认折叠。
- 员工详情加载基础数据和三家渠道的绑定状态。飞书群配置打开后读取 `usage-config` 和 `trigger-rules`，企微群配置打开后只读取 `usage-config`，钉钉直接展示群能力说明。「权限和共享」在打开时单独读取使用范围。渠道白名单提示使用渠道接口返回的范围投影。
- 渠道读取失败时，对应页签显示错误和「重试读取渠道」，员工详情和读取成功的渠道继续显示。重试只读取当前渠道。服务端确认未绑定后显示接入入口。后台刷新按渠道更新结果，保留其他模块的草稿和版本。
- 飞书／钉钉／企微原渠道页均固定展示 @ 能力；Web 配置组件和已有数据保留，但当前 UI 暂不显示 Web 区域。Web／飞书群 @ 能力固定展示，不提供开关。后端仍保留原有共享 mention 字段；保存历史设置原样保留 true/false，旧关闭配置明确提示且不会自动启用。
- 历史后台共用 enabled / limit；各页仅编辑当前渠道的实际启用状态和共用最大条数。飞书、企微各自展示历史设置，钉钉不展示；Web 历史组件保留待 Web 群前端启用。保存不改变其他渠道实际启用状态；若原总开关为关闭，启用当前渠道仅加入该渠道，不意外激活其他旧选择。
- IM 仅飞书显示命名关键词/正则，Web 组件保留但当前无页面入口。列表按当前渠道筛选，后端测试固定当前渠道。规则底层每行 channels 支持 Web、飞书；保存完整规则集合，编辑飞书行不删除 Web-only 行。当前飞书页面编辑共享行时拆分飞书新行并保留原 Web 行，删除仅去除飞书侧；新建仅飞书，不提供 Web 选项。
- 命中测试调用既有 trigger-rules/test 接口，带真实 channel 和完整待测试草稿，不用浏览器另做一套正则解释。
- 保存历史时保留读取快照中的 access、关键词/正则投影和资源版本；冲突交给后端拒绝，不自动重试或静默换版本。
- 规则 PATCH 已成功但后续 usage GET 失败时，保留成功规则并说明刷新失败。禁用 stale 的历史编辑，手动刷新后才能继续。如果另有未保存的历史草稿，先保留并提示取消后刷新，不借新版本悄悄覆盖。

接线通过 `WorkforcePorts.groupPoliciesApi`，真实端口调用现有 usage-config 与 trigger-rules 契约；没有后端业务或权限语义变更。原飞书/企微分卡的同类保存入口在真实模式隐藏，避免重复开关、共同条数被误认为独立参数。

钉钉的「群聊 @ 交互支持」已并入「钉钉群配置」，沿用「尚未验证」状态和群内收发验证提示。钉钉卡片直接展示能力说明。

使用 `node --test test/workforce-original-channels.test.mjs test/workforce-original-root.test.mjs` 验收三家渠道的绑定前后展示、模块顺序、飞书授权明细默认折叠、按需请求和失败渠道单独重试。

回归覆盖 @ 能力无开关及旧关闭配置保留、Web 历史保留其他渠道、规则渠道编辑与未保存草稿测试、Web-only 保留、撤权清空、CAS 冲突以及已保存/刷新失败分离。组件测试注入遵守真实合同的端口，不声称真实渠道收发已验收。
